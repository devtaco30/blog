안녕하세요. 요즘 AI 코딩 도구가 넘쳐나는 시대에, 저는 Anthropic의 Claude Code를 직접 프로젝트에 적용해보면서 느낀 것들을 정리해보려 합니다.

단순 코드 자동완성 도구를 기대했다면 예상 밖일 겁니다. Claude Code는 파일 시스템에 직접 접근하고, 명령어를 실행하고, 외부 서비스와 연동하며, 하위 에이전트를 생성해 작업을 병렬로 처리하는 자율 실행 시스템에 가깝습니다.

이 포스팅은 공식 문서와 실제 Spring Boot + Kafka 기반 주식 매매 엔진 프로젝트 적용 경험을 바탕으로 검증된 내용만 정리했습니다. 2026년 3월 기준입니다.

⚙️ 1. Claude Code란?

터미널에서 claude 명령어 하나로 시작 →
Claude가 프로젝트 전체를 파악 →
파일 읽기/수정/생성, 테스트 실행, Git 커밋까지 직접 처리

터미널 기반 AI 코딩 에이전트입니다. IDE 플러그인이나 웹 UI가 아닌 터미널에서 동작하는 게 핵심 특징이에요. 코드를 "제안"하는 수준이 아니라, 직접 파일을 수정하고 명령어를 실행합니다.

요금제 (2026년 3월 기준)

플랜가격특징
Pro$20/월사용량 제한 있음
Max$100~200/월무제한
Teams / Enterprise별도 문의-

Claude Code만 단독 구매는 안 되고, Claude 구독 후 사용 가능합니다.

제 로컬의 토이프로젝트에서 실행을 해봤습니다. 위처럼 처음 실행하면 workspace 를 trust 하냐고 물어옵니다.

trust 하면 이렇게 귀여운 터미널이 열립니다.

🏗️ 2. 핵심 구조: 6개 레이어

Claude Code의 기능은 6개 레이어가 아래에서 위로 쌓이는 구조입니다. 아래 레이어가 없으면 위 레이어가 제대로 동작하지 않아요.

┌─────────────────────────────────────┐
│  Agent Teams (멀티에이전트 협업)     │  ← 레이어 6 (실험적)
├─────────────────────────────────────┤
│  MCP (외부 서비스 연결)              │  ← 레이어 5
├─────────────────────────────────────┤
│  Hooks (이벤트 자동 실행)            │  ← 레이어 4
├─────────────────────────────────────┤
│  Subagents (병렬 전문가)             │  ← 레이어 3
├─────────────────────────────────────┤
│  Skills & Commands (워크플로우)      │  ← 레이어 2
├─────────────────────────────────────┤
│  CLAUDE.md (프로젝트 기억)           │  ← 레이어 1 (기반)
└─────────────────────────────────────┘
기능역할활성화 방식
CLAUDE.md매 세션 자동 로드되는 프로젝트 규칙자동 (항상)
Skills컨텍스트 기반으로 Claude가 자동 적용하는 워크플로우자동
Commands/명령어로 수동 호출하는 워크플로우수동
Subagents독립 컨텍스트로 작업을 분리 실행하는 전문 에이전트자동 or 명시적 지시
Hooks도구 실행 전/후에 자동으로 트리거되는 스크립트이벤트 기반 자동
MCP외부 서비스(GitHub, DB 등)와 연결하는 플러그인설정 후 항상
Agent Teams에이전트끼리 직접 소통하는 멀티에이전트 팀수동 (실험적)

🚀 3. 설치 및 시작

방법 1 — 공식 인스톨러 (권장)

claude.ai/download 에서 OS에 맞는 인스톨러를 받아 실행하면 끝입니다. Node.js 없이 네이티브 바이너리로 설치됩니다.

방법 2 — npm

# Node.js 18 이상 필요
npm install -g @anthropic-ai/claude-code


# 프로젝트 폴더로 이동 후 실행
cd my-project
claude

처음 실행하면 브라우저가 열리며 Claude 계정 인증을 요청합니다. 인증 완료 후 터미널에서 바로 대화할 수 있어요.

# 프로젝트 초기 설정 (CLAUDE.md 자동 생성)
/init

프로젝트의 루트에서 init 명령을 하게되면, 이 프로젝트를 쭉 scan 하고 'CLAUDE.md' 라는 마크다운을 생성합니다.

📋 4. 레이어 1 — CLAUDE.md: 프로젝트의 기억

CLAUDE.md는 매 세션 시작 시 자동으로 로드되는 마크다운 파일입니다. /compact(컨텍스트 압축) 이후에도 살아남는 유일한 영구 기억이에요.

위치 우선순위

./CLAUDE.md                ← 현재 프로젝트 (가장 우선)
./.claude/CLAUDE.md        ← 숨김 폴더 내 프로젝트 설정
~/.claude/CLAUDE.md        ← 전역 설정 (모든 프로젝트에 적용)

무엇을 써야 하나

# CLAUDE.md 예시

## 프로젝트 개요
Node.js + TypeScript 기반 REST API 서버

## 코드 컨벤션
- 커밋 메시지: feat:, fix:, chore: 접두사 필수
- 테스트 없이 커밋 금지
- src/legacy/ 폴더 절대 수정 금지

## 자주 쓰는 명령어
- 개발 서버: npm run dev
- 테스트: npm test
- 빌드: npm run build

권장 분량: 200줄 이하. 초과하면 .claude/rules/ 폴더로 분할하세요.

컨텍스트 관리 명령어

/compact      # 현재 대화를 요약 → 컨텍스트 창 확보 (80% 도달 시 사용)
/remember     # 특정 내용을 명시적으로 영구 저장

🔧 5. 레이어 2 — Skills & Commands: 반복 작업 자동화

Skills — 자동 발동 워크플로우

Skills는 .claude/skills/ 폴더 안의 마크다운 파일입니다. Claude가 대화 맥락을 보고 자동으로 적용합니다. 별도 코드나 빌드 과정 없이 마크다운만 작성하면 돼요.

.claude/
└── skills/
    ├── tdd-workflow/
    │   └── SKILL.md     ← 테스트 관련 작업 시 자동 활성화
    └── git-deploy/
        └── SKILL.md     ← 배포 관련 작업 시 자동 활성화

<!-- .claude/skills/tdd-workflow/SKILL.md 예시 -->
# TDD 워크플로우

## 발동 조건
테스트 작성, 기능 구현, 버그 수정 요청 시

## 실행 순서
1. 인터페이스 먼저 정의
2. 실패하는 테스트 작성 (RED)
3. 최소한의 구현 코드 작성 (GREEN)
4. 리팩터링 (REFACTOR)
5. 커버리지 80% 이상 확인

Commands — 수동 호출 워크플로우

/슬래시명령어 형태로 원할 때만 직접 실행합니다.

/deploy       # 배포 워크플로우 실행
/review       # 코드 리뷰 실행
/batch        # 코드베이스를 여러 단위로 분해해 병렬 처리 후 각각 PR 생성

Skills vs Commands 선택 기준

상황선택
거의 모든 작업에 적용되길 원함Skill
내가 원할 때만 실행하고 싶음Command
컨텍스트와 무관하게 명시적 제어 필요Command

🤖 6. 레이어 3 — Subagents: 병렬 전문가

Subagents는 독립적인 컨텍스트 창을 가진 전문화된 하위 에이전트입니다. 메인 세션의 컨텍스트를 소비하지 않고 별도로 작업을 처리하고, 완료 후 결과만 리포트합니다.

정의 방법

<!-- .claude/agents/code-reviewer.md -->
---
name: code-reviewer
description: 코드 품질, 보안, 유지보수성 관점에서 코드를 리뷰합니다
tools: Read, Glob, Grep
model: sonnet
---

당신은 시니어 코드 리뷰어입니다.
각 이슈에 대해 현재 코드, 문제점, 개선된 코드를 함께 제시하세요.

자연어로도 호출할 수 있습니다:

"code-reviewer 에이전트를 불러서 src/auth/ 폴더 전체 리뷰해줘"

Claude Code 내장 Subagents

  • Explore: 파일 탐색 및 코드베이스 파악
  • Plan: 구현 계획 수립
  • General-purpose: 복잡한 멀티스텝 작업

Subagents가 효과적인 상황

  • 50개 이상의 파일을 분석할 때 (메인 컨텍스트 보호)
  • 독립적인 작업을 병렬로 처리할 때
  • 특정 도구만 허용하는 제한된 환경이 필요할 때

🪝 7. 레이어 4 — Hooks: 이벤트 기반 자동 실행

Hooks는 특정 이벤트 발생 시 자동으로 실행되는 스크립트입니다. Claude의 작업에 자동 검증, 차단, 후처리를 붙일 수 있습니다.

Hook 종류

Hook실행 시점차단 가능 여부
PreToolUse도구 실행 직전✅ (exit code 2)
PostToolUse도구 실행 직후❌
StopClaude 응답 완료 후❌
SessionEnd세션 종료 시❌

설정 방법

// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/validate-command.sh"
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "npm test -- --watchAll=false"
          }
        ]
      }
    ]
  }
}

Hook에서 exit 2로 종료하면 Claude가 해당 작업을 차단하고 오류 메시지를 받습니다.

#!/bin/bash
# 민감한 파일을 커밋하려 할 때 차단하는 예시
if git diff --cached --name-only | grep -qE '\.(env|key|pem)$'; then
  echo "BLOCKED: 민감한 파일이 포함되어 있습니다"
  exit 2  # exit 2 = Claude에게 차단 메시지 전달
fi

🔌 8. 레이어 5 — MCP: 외부 서비스 연결

MCP(Model Context Protocol)는 Anthropic이 공개한 오픈 표준으로, Claude Code가 외부 서비스에 연결하는 방식입니다. GitHub, Postgres, Slack, Notion 등 300개 이상의 서비스가 MCP 서버를 제공합니다.

추가 방법

# HTTP 방식 (원격 서버)
claude mcp add --transport http notion https://mcp.notion.com/mcp

# stdio 방식 (로컬 서버)
claude mcp add --transport stdio github -- npx @modelcontextprotocol/server-github

# 등록된 MCP 서버 목록 확인
/mcp

팀 공유 설정

.mcp.json 파일을 프로젝트 루트에 두면 팀 전체가 같은 MCP 설정을 공유할 수 있습니다.

{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}

⚠️ 컨텍스트 주의사항

MCP 서버가 많아질수록 컨텍스트 창이 줄어듭니다. 동시에 활성화하는 MCP는 10개 이하, 총 도구 수는 80개 이하로 유지하는 것을 권장해요. 200K 토큰 컨텍스트가 MCP 도구 정의만으로 70K까지 줄어들 수 있습니다.

👥 9. 레이어 6 — Agent Teams: 멀티에이전트 협업 (실험적)

Agent Teams는 에이전트들이 서로 직접 메시지를 주고받으며 협업할 수 있는 기능입니다. 2026년 현재 실험적 기능으로, 명시적으로 활성화해야 합니다.

활성화 방법

// .claude/settings.json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

Agent Teams 구조

리드 에이전트 (Lead)
├── 팀원 A (Teammate) ─ 직접 메시지 가능 ─┐
├── 팀원 B (Teammate) ─────────────────── 서로 소통
└── 팀원 C (Teammate) ──────────────────┘
  • 각 팀원은 독립적인 컨텍스트 창 보유
  • 팀원끼리 직접(P2P) 메시지 가능 — Subagents와의 핵심 차이
  • 공유 태스크 리스트를 통해 작업 분배
  • 팀원 수에 비례해 토큰 비용 증가 (3명 팀 ≈ 3~4배)

Subagents vs Agent Teams

구분SubagentsAgent Teams
에이전트 소통리드에게만 보고팀원 간 P2P 직접 소통
적합한 상황독립적인 분석·검색서로 결과를 공유하며 협업
토큰 비용낮음높음 (팀원 수 비례)
안정성안정실험적

권장: Subagents로 먼저 시작하고, 에이전트 간 실시간 조율이 필요할 때만 Agent Teams로 업그레이드하세요.

🌳 10. Git Worktrees: 충돌 없는 병렬 실행

Git Worktrees는 같은 저장소에서 여러 브랜치를 별도 디렉터리에 동시에 체크아웃하는 Git 기능입니다. Claude Code에서 병렬 작업 시 파일 충돌을 방지합니다.

# 새 워크트리 생성 (브랜치 자동 생성)
git worktree add .claude/worktrees/feat-1024 -b feat-1024

# 또는 Claude Code에서 직접
claude --worktree feat-1024
구분SubagentsAgent TeamsWorktrees
파일 격리❌❌✅ (브랜치 분리)
에이전트 소통리드에게만P2P 가능없음 (완전 독립)
주요 용도독립 분석협업·검증동시 파일 수정

Worktrees는 에이전트 기능이 아니라 Git 기능입니다. 위 두 가지와 조합해서 씁니다.

📁 11. 전체 디렉터리 구조

your-project/
├── CLAUDE.md                        ← 프로젝트 헌법 (필수)
├── .mcp.json                        ← MCP 서버 설정 (팀 공유)
│
└── .claude/
    ├── settings.json                ← Hooks, Agent Teams 활성화
    ├── rules/                       ← CLAUDE.md 분할 규칙 (200줄 초과 시)
    │   ├── coding-style.md
    │   └── git-conventions.md
    ├── agents/                      ← Subagent 정의
    │   ├── code-reviewer.md
    │   └── security-checker.md
    ├── skills/                      ← 자동 발동 워크플로우
    │   ├── tdd-workflow/
    │   │   └── SKILL.md
    │   └── git-deploy/
    │       └── SKILL.md
    └── worktrees/                   ← 병렬 실행 시 자동 생성
        └── .gitkeep                 ← .gitignore에 worktrees/ 추가 필요

🗺️ 12. 실전 세팅 순서

아래 레이어일수록 위 레이어의 컨텍스트를 필요로 합니다. CLAUDE.md 없이 Subagents를 만들면 에이전트가 프로젝트 맥락을 모른 채 동작하게 됩니다.

STEP 1  설치 & /init                              ★ 필수
        └─ npm install -g @anthropic-ai/claude-code
           프로젝트 폴더에서 claude 실행 후 /init

STEP 2  CLAUDE.md 작성                            ★ 가장 중요
        └─ /init으로 생성된 초안을 프로젝트에 맞게 다듬기
           코드 컨벤션, 금지 사항, 자주 쓰는 명령어 추가

STEP 3  MCP 연결                                  ★ 권장

CLAUDE.md — 핵심은 "하지 말 것"

CLAUDE.md에서 가장 효과적이었던 건 부정 규칙(negative rules) 이었습니다. Claude는 선의로 코드를 "개선"하려는 경향이 있는데, 이를 명시적으로 막는 게 핵심이에요.

## 하지 말 것

- 요청하지 않은 리팩토링, 에러 핸들링, 주석 추가
- main 직접 푸시
- commit message, PR 본문에 AI 도구 사용 흔적 포함
- `docs/` 폴더 및 하위 파일 커밋에 포함

"코드 수정과 그에 대응하는 테스트는 같은 커밋에 묶는다"는 원칙도 명시했습니다. 이 규칙이 없으면 Claude는 코드 변경 커밋과 테스트 추가 커밋을 분리하는 경향이 있어요.

Hooks — 자동 안전망

protect-files.sh — 민감 파일 수정 차단 (PreToolUse)

application-local.yml, .env 같은 파일을 Claude가 실수로 수정하는 것을 막습니다.

#!/bin/bash
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

PROTECTED=("application-local.yml" "application-secret.yml" ".env" ".env.local")

for pattern in "${PROTECTED[@]}"; do
    if [[ "$FILE_PATH" == *"$pattern"* ]]; then
        echo "보호된 파일 수정 차단: $FILE_PATH" >&2
        exit 2
    fi
done

test-on-change.sh — 모듈별 테스트 자동 실행 (PostToolUse)

파일을 수정한 직후 해당 모듈의 테스트만 실행합니다. 전체 빌드 대신 수정된 모듈만 테스트하므로 빠르고, 테스트가 실패하면 Claude가 결과를 받아 스스로 수정합니다.

#!/bin/bash
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

# 테스트 파일 수정 시는 스킵 (무한 루프 방지)
if [[ "$FILE_PATH" == */test/* ]]; then exit 0; fi

if [[ "$FILE_PATH" == */trading/* ]]; then
    ./gradlew :trading:test --quiet 2>&1 | tail -15
elif [[ "$FILE_PATH" == */api/* ]]; then
    ./gradlew :api:test --quiet 2>&1 | tail -15
fi

*/test/* 경로 스킵이 중요합니다. 테스트 파일을 수정했을 때도 테스트를 실행하면 → 테스트 실패 시 다시 수정 → 또 테스트 실행 → 무한 루프가 발생합니다.

Stop Hook — 응답 완료 후 컴파일 검증

Claude가 응답을 완료할 때마다 전체 빌드를 실행해 컴파일 에러를 잡습니다. -x test로 테스트는 제외해 빠르게 실행돼요.

./gradlew build -x test --quiet 2>&1 | tail -10

모듈별 CLAUDE.md

루트 CLAUDE.md 외에 api/CLAUDE.md를 별도로 두었습니다. api 모듈은 Kafka 설계 원칙이 특히 중요하기 때문이에요.

<!-- api/CLAUDE.md -->
## Kafka 설계 원칙

파티션 키는 반드시 stockCode. 같은 종목의 메시지 순서 보장이 Single Writer의 전제.

Kafka 발행은 반드시 DB 커밋 후(afterCommit).
DB 커밋 전 발행 → Consumer가 DB 조회 시 주문 없음.

ack-mode: manual_immediate — 처리 완료 후 명시적 acknowledge.
자동 커밋 시 처리 실패해도 offset이 커밋되어 메시지 유실 가능.

Claude가 api 모듈 코드를 작성할 때 이 파일이 추가로 로드되어 Kafka 관련 원칙을 자동으로 적용합니다.

실제로 겪은 것들

Subagents vs Skills — 처음엔 개념이 헷갈렸다

.claude/agents/를 설정하려고 했는데, Claude가 처음에 "Subagent는 빌트인만 가능하고 사용자가 직접 정의할 수 없다"고 잘못 안내했습니다. .claude/agents/ 디렉토리에 마크다운 파일로 정의하면 된다는 걸 내가 먼저 알고 있었고, 그 사실을 말했더니 인정했어요.

공식 문서를 보지 않고 Claude 말만 믿었으면 엉뚱한 방향으로 설정했을 겁니다. 도구 자체의 구조에 관한 질문은 직접 문서를 확인하고 Claude의 답변을 검증하는 게 맞습니다.

Hooks를 한 줄로 정의하면

"인간이 없어도 자동으로 테스트·린트·로그를 실행하는 미들웨어". Claude가 파일을 수정하면 Hook이 트리거되고, 결과를 다시 Claude에게 피드백하면 Claude가 스스로 수정합니다. 이 루프를 사람이 개입하지 않고 돌리는 구조예요.

Agent Teams는 의도적으로 제외했다

팀원 수만큼 토큰 비용이 선형으로 늘어납니다. 3명 팀이면 단순 계산으로 3배예요. 이 프로젝트에서 에이전트 간 실시간 조율이 필요한 작업은 없어서 Subagents까지만 쓰기로 결정했습니다.

.claude/는 .gitignore에 넣어야 한다

설정이 끝난 뒤 커밋하려고 했는데, .claude/와 CLAUDE.md가 스테이징되어 있었습니다. 이 파일들은 개발자 로컬 환경 설정이지 프로젝트 코드베이스에 포함될 내용이 아니에요. .gitignore에 추가해서 커밋 대상에서 제외했습니다.

⚖️ 16. Cursor AI vs Claude Code — 둘 다 써본 입장에서

제 첫 AI 코딩 툴은 Cursor였습니다. Claude Code로 넘어오면서 느낀 차이를 솔직하게 정리합니다.

Cursor의 강점 — 편의성

Cursor는 VSCode 기반이라 설치하는 순간 기존 개발 환경 그대로 쓸 수 있습니다.

참조가 정말 편하다

  • @파일명, @폴더명을 타이핑하면 자동완성으로 파일 참조
  • 드래그해서 컨텍스트에 추가하는 것도 직관적
  • 에디터 안에서 모든 게 해결됨

MCP 설정이 GUI로

  • Settings 패널에서 클릭 몇 번으로 MCP 서버 추가
  • JSON 직접 편집 없이 연동 가능
  • 진입장벽이 낮음

Claude Code의 강점 — 자율 실행

Claude Code는 UI가 투박합니다. 터미널이 전부고, 파일 참조도 직접 경로를 지정해야 해요. 그런데 막상 써보면 에이전트 성능 자체가 다릅니다.

"제안"이 아니라 "실행"

Cursor:   내가 요청 → AI가 코드 제안 → 내가 Accept/Reject → 반복
Claude Code: 내가 목표 제시 → AI가 파일 읽고 수정하고 테스트 돌리고 → 결과 보고

Cursor는 "AI가 제안, 내가 판단" 구조입니다. 한 번에 한 파일, 한 번에 한 변경을 내가 승인해야 해요.

Claude Code는 "내가 목표, AI가 실행" 구조입니다. "이 기능 추가해줘"라고 하면 관련 파일을 스스로 찾아서 읽고, 수정하고, 테스트 실행하고, 실패하면 고치고, 완료되면 보고합니다.

어떤 상황에 뭘 쓸까

상황추천
특정 파일 몇 개만 빠르게 수정Cursor
기존 IDE 환경 그대로 쓰고 싶음Cursor
기능 단위로 end-to-end 구현Claude Code
테스트, 빌드, 커밋까지 자동화하고 싶음Claude Code
AI 코딩 툴 처음 입문Cursor (진입장벽 낮음)

결론: Cursor는 편의성, Claude Code는 자율성. 처음 AI 코딩 툴을 접한다면 Cursor로 시작해 감을 잡고, 더 복잡한 작업을 자동화하고 싶어질 때 Claude Code로 넘어오는 게 자연스러운 경로 같습니다.

💡 핵심 정리

Claude Code는 단순한 코딩 어시스턴트를 넘어 개발 워크플로우 전체를 자동화하는 에이전트 프레임워크입니다. 레이어를 하나씩 추가해가며 점진적으로 도입하면 됩니다.

시작 경로 추천:

CLAUDE.md 작성 → 실제로 써보기 (1~2주)
→ 자주 반복되는 작업을 Skills로 → Hooks로 실수 방지
→ 큰 프로젝트에서 Subagents 도입 → 필요시 MCP 연결

가장 중요한 건 CLAUDE.md입니다. 나머지 기능들이 얼마나 잘 동작하는지는 Claude가 프로젝트를 얼마나 잘 이해하고 있느냐에 달려 있고, 그 기반이 CLAUDE.md이기 때문입니다.
