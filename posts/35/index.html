EST AI - Machine Learning 실습 (타이타닉 데이터 시각화 및 특성공학)

Deck, Pclass, 성별, 승선항, 연령에 따라 생존·사망이 어떻게 갈리는지 타이타닉 데이터를 시각화합니다. | 시각화로 본 패턴을 바탕으로 Family_Size를 만들고 Binning과 One-hot Encoding을 적용합니다.

2025년 12월 11일 오후 09:17

📚 오늘의 학습 내용

오늘은 타이타닉 데이터의 시각화와 **특성공학(Feature Engineering)**을 진행했습니다. 다양한 시각화 기법을 통해 데이터의 패턴을 파악하고, Family_Size 생성, Binning을 통한 범주화, One-hot Encoding 등 데이터 전처리 기법을 학습했습니다.

1️⃣ 데이터 시각화

1-1. Deck에 따른 생존/사망 시각화

sns.countplot(data=train, x='Deck', hue='Survived')
plt.show()

해석:

  • hue: 분할 기준 → 나타내고자 하는 것 (여기서는 생존 여부)
  • M 층에 있는 (결측치인) 사람들은 살아남지 못해서 어느 층인지 알지 못했을 것이다

1-2. Pclass에 따른 생존/사망 시각화

sns.countplot(data=train, x='Pclass', hue='Survived')
plt.show()

해석:

  • 3등석의 사람들이 많이 죽었다

1-3. Deck과 Pclass 시각화 연결

sns.countplot(data=train, x='Deck', hue='Pclass')
plt.legend()
plt.show()

해석:

  • 결측치인 M은 대부분이 3등석 사람들이었다
  • 임의의 층 M에는 3등석인 사람이 많았다
  • Pclass가 3등석이어서 사망자가 많았음을 확인
  • M이라는 데이터는 더 이상 신경쓰지 않는다. Pclass 데이터를 통해 알 수 있음

2️⃣ 특성공학 (Feature Engineering)

2-1. Family_Size 생성

목적: Parch와 SibSp를 합쳐서 가족의 전체 크기를 나타내는 새로운 컬럼 생성

# train
train['Family_Size'] = train['Parch'] + train['SibSp'] + 1  # 본인도 포함해야 하므로 + 1
train['Family_Size']

# test
test['Family_Size'] = test['Parch'] + test['SibSp'] + 1
test['Family_Size']

설명:

  • Parch: 부모/자식 수 (같이 탑승한)
  • SibSp: 형제자매/배우자 수 (같이 탑승한)
  • +1: 본인 자신
  • 따라서 Family_Size = 부모/자식 + 형제/배우자 + 본인 = 전체 가족 구성원 수

Family_Size 시각화

sns.countplot(data=train, x='Family_Size', hue='Survived')
plt.show()

인사이트:

  • 1명일 때는 사망율이 높음 (alone)

2-2. Family_Size 범주화 (Binning)

가족 크기별 분류 기준

  • 1명 (alone): 사망율이 높음
  • 2~4명 (small): 중간 규모 가족
  • 5~11명 (large): 대가족

데이터 변환 개념

  • 비닝 (Binning): 숫자형 → 범주형 변환

    • 연속형/수치형 데이터를 구간으로 나누어 범주로 만드는 작업
    • 예: Family_Size (1, 2, 3, ...) → "alone", "small", "large"

  • 인코딩 (Encoding): 범주형 → 숫자형 변환

    • 범주형 데이터를 숫자로 변환하는 작업
    • 예: "male", "female" → 0, 1

Binning 구현

bins = [0, 1, 4, 11] 
# (0, 1] -> 0 초과 1 이하
# (1, 4] -> 1 초과 4 이하
# (4, 11] -> 4 초과 11 이하

labels = ['Alone', 'Small', 'Large']

# cut: 연속적인 수치형 데이터를 '일정 범위'로 나누어 줌
train['Family_group'] = pd.cut(train['Family_Size'], bins=bins, labels=labels)
test['Family_group'] = pd.cut(test['Family_Size'], bins=bins, labels=labels)

Family_group 시각화

sns.countplot(data=train, x='Family_group', hue='Survived')
plt.show()

2-3. 불필요한 컬럼 삭제

삭제 대상:

  • Name: 이름 (고유값이 많아 학습에 의미 없음)
  • Ticket: 티켓번호 (고유값이 많아 학습에 의미 없음)
  • SibSp: 형제자매/배우자 수 (Family_Size로 대체)
  • Parch: 부모/자식 수 (Family_Size로 대체)
  • Family_Size: 숫자형 (Family_group으로 대체)
# drop, axis=1, inplace=True로 바로 적용
train.drop(['Name', 'Ticket', 'SibSp', 'Parch', 'Family_Size'], axis=1, inplace=True)
test.drop(['Name', 'Ticket', 'SibSp', 'Parch', 'Family_Size'], axis=1, inplace=True)

2-4. One-hot Encoding

목적: 범주형 데이터를 숫자형으로 변환하여 모델 학습에 사용

대상 컬럼:

  • Sex (male, female)
  • Embarked (C, Q, S)
  • Deck (A, B, C, D, E, F, G, M, T)
  • Family_group (Alone, Small, Large)
# object type인 Sex, Embarked, Deck, Family_group
X_train_one_hot = pd.get_dummies(X_train)
X_test_one_hot = pd.get_dummies(X_test)

결과:

  • 각 범주형 값이 별도의 컬럼으로 생성됨
  • 예: Sex_male, Sex_female, Embarked_C, Embarked_Q, Embarked_S 등

주의사항:

  • train과 test 데이터의 컬럼 수가 다를 수 있음 (예: test에 없는 Deck_T)
  • 모델 학습 시 컬럼 순서와 이름이 일치해야 함
  • 해결: X_test_one_hot = X_test_one_hot[X_train_one_hot.columns]로 재정렬

💡 핵심 정리

배운 것

  • 시각화 기법:

    • sns.countplot(): 범주형 데이터의 빈도 시각화
    • sns.violinplot(): 수치형 데이터의 분포 시각화
    • hue 파라미터: 분할 기준 설정

  • 특성공학 (Feature Engineering):

    • Family_Size 생성: Parch + SibSp + 1 (본인 포함)
    • Binning: pd.cut()을 사용한 숫자형 → 범주형 변환
    • One-hot Encoding: pd.get_dummies()를 사용한 범주형 → 숫자형 변환

  • 데이터 정리:

    • 불필요한 컬럼 삭제: drop() 메서드 사용
    • 컬럼 순서 재정렬: 학습 데이터의 컬럼 순서에 맞춰 정렬

인사이트

  • 시각화를 통한 패턴 발견:

    • 1명일 때 사망율이 높음 → alone 그룹으로 분류
    • 3등석 사망율이 높음 → Pclass가 중요한 특성

  • 특성공학의 중요성:

    • 단순히 원본 데이터를 사용하는 것보다 의미있는 특성을 만들어내는 것이 모델 성능 향상에 도움
    • Family_Size처럼 여러 컬럼을 조합하여 새로운 특성 생성

  • One-hot Encoding 주의사항:

    • train과 test 데이터의 컬럼 수가 다를 수 있음
    • 모델 학습 시 사용한 컬럼 순서와 이름을 정확히 맞춰야 함
