안녕하세요. Java/Kotlin 백엔드 개발자로서 HashMap의 내부 동작 원리를 이해하는 것은 성능 최적화와 버그 예방에 필수적입니다.

본 포스팅(1부)에서는 HashMap의 기본 구조와 해시 코드를 인덱스로 변환하는 AND 연산의 원리를 다룹니다.

2부에서는 putVal과 resize 메서드의 실제 코드를 라인별로 분석합니다.

🎯 1. HashMap의 기본 구조

Map과 HashMap의 관계

⚠️ 핵심: Map은 Key-Value를 저장하는 인터페이스, HashMap은 내부적으로 배열을 사용하는 구현체입니다!

interface Map<K, V> {
    V put(K key, V value);
    V get(Object key);
}

class HashMap<K, V> implements Map<K, V> {
    Node<K,V>[] table;  // ⚠️ 핵심: 내부적으로 배열 사용
    int size;
    int threshold;
    float loadFactor;
}

HashMap의 내부 구조

⚠️ 핵심: HashMap은 Node<K,V>[] table 배열로 Key-Value를 저장합니다!

기본 구조:

Node<K,V>[] table  (버킷 배열)
├─ [0] → null                    (비어있음)
├─ [1] → Node                    (Node 하나만 있음)
├─ [2] → Node → Node → Node      (연결 리스트, 해시 충돌)
├─ [3] → TreeNode                (트리로 변환됨, Java 8+)
└─ ...

Node 구조:

static class Node<K,V> {
    final int hash;      // 키의 해시 코드
    final K key;         // 키
    V value;             // 값
    Node<K,V> next;      // 다음 노드 (연결 리스트, 같은 Bucket 내)
}

⚠️ 핵심:

  • Bucket = 배열의 각 인덱스 (table[0], table[1], ...)
  • Node = Bucket에 저장되는 데이터 (Key, Value 포함)
  • 해시 충돌 시: 같은 Bucket에 연결 리스트로 저장 (next로 연결)
  • 연결 리스트가 8개 이상: 트리로 변환 (성능 최적화)

🔑 2. 해시 코드와 인덱스 계산

⚠️ 핵심: AND 연산으로 인덱스 계산

HashMap은 나머지 연산(%) 대신 AND 연산(&)을 사용합니다!

이유:

  1. 성능: AND 연산은 비트 연산으로 매우 빠름
  2. 제약: 배열 크기가 항상 2의 거듭제곱 (16, 32, 64, ...)

AND 연산의 원리:

배열 크기: n = 16 (2^4)
n - 1:     15 = 1111 (2진수, 하위 4비트만 1)

해시 코드: hash = 10110110 (182)

인덱스 계산:
  10110110  (hash)
& 00001111  (n - 1 = 15)
----------
  00000110  = 6

→ 인덱스 6번 버킷에 저장

⚠️ 핵심: (n - 1)은 비트 마스크 역할을 하며, 해시 코드의 하위 비트만 추출합니다!

2의 거듭제곱의 특징:

16 = 2^4 = 10000
15 = 16 - 1 = 01111  ← 하위 4비트만 1

32 = 2^5 = 100000
31 = 32 - 1 = 011111  ← 하위 5비트만 1

문제점: 해시 코드의 상위 비트는 무시됨

  • 해시 코드의 하위 비트만 사용 → 충돌 가능성 증가
  • 해결책: hash() 메서드로 해시 코드 재분산 (상위 비트 정보를 하위 비트에 반영)

📝 3. putVal과 resize 개요

putVal 메서드

⚠️ 핵심: putVal은 해시 코드를 인덱스로 변환하고, 버킷에 Node를 저장하는 메서드입니다!

주요 단계:

  1. 해시 코드를 인덱스로 변환: (n - 1) & hash
  2. 버킷 확인: table[i]가 null인지 확인
  3. 해시 충돌 처리: 키 비교 및 연결 리스트/트리 처리
  4. 크기 확인 및 resize: size > threshold면 resize 호출

resize 메서드

⚠️ 핵심: resize는 배열 크기를 2배로 늘리고, 모든 요소를 재배치하는 메서드입니다!

주요 단계:

  1. 새 배열 크기 계산: newCap = oldCap << 1 (2배)
  2. 새 배열 생성: Node<K,V>[] newTab
  3. 기존 요소 재배치: 모든 Node를 새 배열로 이동
  4. 인덱스 재계산: (newCap - 1) & hash

resize 조건:

  • ++size > threshold (기본 로드 팩터 0.75)
  • 예: 배열 크기 16 → 임계값 12 → 13번째 요소 추가 시 resize

🎓 핵심 정리

  1. HashMap의 내부 구조: Node<K,V>[] table 배열 사용
  2. 인덱스 계산: (n - 1) & hash - AND 연산으로 하위 비트만 추출
  3. 해시 충돌 처리: 같은 Bucket에 연결 리스트로 저장
  4. resize: 배열 크기 2배 증가, 모든 요소 재배치
