[6년차 쯤 되면 좀 알자] HashMap putVal과 resize - 2부 -

안녕하세요. Java/Kotlin 백엔드 개발자로서 HashMap의 내부 동작 원리를 이해하는 것은 성능 최적화와 버그 예방에 필수적입니다.

본 포스팅(2부)에서는 putVal과 resize 메서드의 실제 코드를 라인별로 분석합니다. 특히 해시 코드와 n-1의 AND 연산, 그리고 resize에서 oldCap과의 AND 연산이 전체 해시 코드에 미치는 영향을 설명합니다.

1부에서는 HashMap의 기본 구조와 해시 인덱스 계산 방식을 다뤘습니다.

🎯 1. putVal 메서드 코드 분석

⚠️ putVal의 if-else 구조 분석

멘토가 강조한 부분: putVal의 조건문 구조

전체 구조:

if (버킷이 비어있음) {
    // 새 Node 생성
}
else {
    if (첫 번째 Node의 키와 같음) {
        // 값 업데이트
    }
    else if (트리 노드) {  // ⚠️ "fr" = Tree (TreeNode)
        // 트리에서 처리
    }
    else {  // 연결 리스트
        // 연결 리스트 탐색
    }
}

⚠️ 핵심: 이 구조는 해시 충돌을 처리하는 3가지 경우를 다룹니다!

  1. 첫 번째 if: 버킷이 비어있음 → 새 Node 생성
  2. 첫 번째 else 내부:
    • if: 첫 번째 Node의 키와 같음 → 값 업데이트
    • else if: 트리 노드 (TreeNode) → 트리에서 처리
    • else: 연결 리스트 → 순회하며 키 찾기 또는 추가

⚠️ putVal 메서드 전체 코드 라인별 주석

final V putVal(int hash, K key, V value, boolean onlyIfAbsent, boolean evict) {
    // 1. 변수 선언
    Node<K,V>[] tab; Node<K,V> p; int n, i;
    
    // 2. 테이블 초기화 확인 (lazy initialization)
    if ((tab = table) == null || (n = tab.length) == 0)
        n = (tab = resize()).length;
    
    // 3. ⚠️ 핵심: 인덱스 계산과 버킷 확인을 한 줄에 처리
    // i = (n - 1) & hash: AND 연산으로 인덱스 계산
    // p = tab[i]: 해당 인덱스의 버킷 접근
    if ((p = tab[i = (n - 1) & hash]) == null)
        // 4. 버킷이 비어있으면 새 Node 생성
        tab[i] = newNode(hash, key, value, null);
    else {
        // 5. 해시 충돌 처리
        Node<K,V> e; K k;
        
        // 6. 경우 1: 첫 번째 Node의 키와 같음
        // ⚠️ 해시 코드 비교가 먼저! (p.hash == hash)
        if (p.hash == hash &&
            ((k = p.key) == key || (key != null && key.equals(k))))
            e = p;
        
        // 7. 경우 2: 트리 노드 (TreeNode) 
        // 연결 리스트가 8개 이상이면 트리로 변환됨
        else if (p instanceof TreeNode)
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);
        
        // 8. 경우 3: 연결 리스트 탐색
        else {
            for (int binCount = 0; ; ++binCount) {
                if ((e = p.next) == null) {
                    // 9. 연결 리스트 끝에 새 Node 추가
                    p.next = newNode(hash, key, value, null);
                    // 10. 연결 리스트가 8개 이상이면 트리로 변환
                    if (binCount >= TREEIFY_THRESHOLD - 1)
                        treeifyBin(tab, hash);
                    break;
                }
                // 11. 연결 리스트에서 키를 찾음
                if (e.hash == hash &&
                    ((k = e.key) == key || (key != null && key.equals(k))))
                    break;
                // 12. 다음 Node로 이동 (순회)
                p = e;
            }
        }
        
        // 13. 기존 키가 있으면 값 업데이트
        if (e != null) {
            V oldValue = e.value;
            if (!onlyIfAbsent || oldValue == null)
                e.value = value;
            afterNodeAccess(e);
            return oldValue;
        }
    }
    
    // 14. 새 키가 추가된 경우
    ++modCount;
    // 15. ⚠️ 핵심: 요소 개수가 임계값을 넘으면 resize 호출
    if (++size > threshold)
        resize();
    afterNodeInsertion(evict);
    return null;
}

⚠️ 핵심 포인트:

  1. 인덱스 계산: (n - 1) & hash - AND 연산으로 해시 코드를 인덱스로 변환
  2. 해시 충돌 처리: 해시 코드 비교 → 키 비교 → 연결 리스트/트리 처리
  3. resize 조건: ++size > threshold - 요소 개수가 임계값을 넘으면 resize

🔄 2. resize 메서드 코드 분석

⚠️ resize 메서드 전체 코드 라인별 주석

final Node<K,V>[] resize() {
    // 1. 기존 배열 크기 확인
    Node<K,V>[] oldTab = table;
    int oldCap = (oldTab == null) ? 0 : oldTab.length;
    int oldThr = threshold;
    int newCap, newThr = 0;
    
    // 2. 새 배열 크기 계산
    if (oldCap > 0) {
        // 2-1. 최대 크기에 도달한 경우
        if (oldCap >= MAXIMUM_CAPACITY) {
            threshold = Integer.MAX_VALUE;
            return oldTab;
        }
        // 2-2. ⚠️ 핵심: 배열 크기 2배 증가
        else if ((newCap = oldCap << 1) < MAXIMUM_CAPACITY &&
                 oldCap >= DEFAULT_INITIAL_CAPACITY)
            newThr = oldThr << 1; // 임계값도 2배
    }
    // 2-3. 초기화 시 threshold가 설정된 경우
    else if (oldThr > 0)
        newCap = oldThr;
    // 2-4. 기본값 사용 (new HashMap())
    else {
        newCap = DEFAULT_INITIAL_CAPACITY;
        newThr = (int)(DEFAULT_LOAD_FACTOR * DEFAULT_INITIAL_CAPACITY);
    }
    
    // 3. 임계값이 0인 경우 계산 (oldThr > 0인 경우)
    if (newThr == 0) {
        float ft = (float)newCap * loadFactor;
        newThr = (newCap < MAXIMUM_CAPACITY && ft < (float)MAXIMUM_CAPACITY ?
                  (int)ft : Integer.MAX_VALUE);
    }
    
    // 4. 새 배열 생성
    threshold = newThr;
    Node<K,V>[] newTab = (Node<K,V>[])new Node[newCap];
    table = newTab;
    
    // 5. 기존 요소 재배치
    if (oldTab != null) {
        for (int j = 0; j < oldCap; ++j) {
            Node<K,V> e;
            if ((e = oldTab[j]) != null) {
                oldTab[j] = null;
                
                // 5-1. 버킷에 Node가 하나만 있음
                if (e.next == null)
                    newTab[e.hash & (newCap - 1)] = e;
                
                // 5-2. 트리 노드
                else if (e instanceof TreeNode)
                    ((TreeNode<K,V>)e).split(this, newTab, j, oldCap);
                
                // 5-3. 연결 리스트 - ⚠️ 핵심 부분!
                else {
                    Node<K,V> loHead = null, loTail = null;
                    Node<K,V> hiHead = null, hiTail = null;
                    Node<K,V> next;
                    do {
                        next = e.next;
                        // ⚠️ 핵심: e.hash & oldCap 연산
                        // 해시 코드의 특정 비트(5번째 비트) 확인
                        if ((e.hash & oldCap) == 0) {
                            // 기존 인덱스 유지
                            if (loTail == null)
                                loHead = e;
                            else
                                loTail.next = e;
                            loTail = e;
                        }
                        else {
                            // 새 인덱스로 이동 (기존 + oldCap)
                            if (hiTail == null)
                                hiHead = e;
                            else
                                hiTail.next = e;
                            hiTail = e;
                        }
                    } while ((e = next) != null);
                    
                    if (loTail != null) {
                        loTail.next = null;
                        newTab[j] = loHead;  // 기존 인덱스 j
                    }
                    if (hiTail != null) {
                        hiTail.next = null;
                        newTab[j + oldCap] = hiHead;  // 새 인덱스 j + oldCap
                    }
                }
            }
        }
    }
    return newTab;
}

⚠️ 3. resize에서 사용되는 두 가지 AND 연산

1. 첫 번째 AND 연산: e.hash & oldCap

⚠️ 핵심: 해시 코드의 특정 비트(5번째 비트)를 확인하여 연결 리스트를 분할합니다!

예시:

기존 배열 크기: oldCap = 16 = 10000 (2진수, 5번째 비트가 1)
해시 코드:     hash = 10110110 (182)

AND 연산:
  10110110  (hash)
& 00010000  (oldCap = 16)
----------
  00010000  = 16 (0이 아님)

→ 해시 코드의 5번째 비트가 1
→ 새 인덱스 = 기존 인덱스 + oldCap

동작:

  • (e.hash & oldCap) == 0: 5번째 비트가 0 → 기존 인덱스 유지 (newTab[j])
  • (e.hash & oldCap) != 0: 5번째 비트가 1 → 새 인덱스로 이동 (newTab[j + oldCap])

2. 두 번째 AND 연산: e.hash & (newCap - 1)

⚠️ 핵심: 새 인덱스를 계산합니다!

예시:

새 배열 크기: newCap = 32 = 2^5
newCap - 1:   31 = 11111 (하위 5비트가 모두 1)

해시 코드: hash = 10110110 (182)

AND 연산:
  10110110  (hash)
& 00011111  (newCap - 1 = 31)
----------
  00010110  = 22

→ 새 인덱스 22번 버킷에 저장

비교:

기존 인덱스: (oldCap - 1) & hash = 15 & hash (하위 4비트만 사용)
새 인덱스:   (newCap - 1) & hash = 31 & hash (하위 5비트 사용)

차이점: 5번째 비트가 추가됨

🎓 4. AND 연산이 해시 코드에 미치는 영향

⚠️ 핵심: AND 연산은 해시 코드의 하위 비트만 사용합니다!

문제점:

  • 해시 코드의 상위 비트는 무시됨
  • 해시 분산이 좋지 않으면 충돌 증가

해결책: 해시 코드 재분산

static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

동작:

  • 상위 16비트를 하위 16비트와 XOR
  • 상위 비트 정보를 하위 비트에 반영 → 해시 분산 개선

⚠️ 핵심: AND 연산자가 전체 해시 코드에 미치는 영향

멘토가 강조한 부분: AND 연산자가 2개 나오는데, 이들이 해시 코드에 어떤 영향을 미치는가?

1. putVal에서의 AND 연산: (n - 1) & hash

영향:

  • 해시 코드의 하위 비트만 사용하여 인덱스 생성
  • 상위 비트는 무시됨 → 충돌 가능성 증가
  • 예: 해시 코드가 18, 34, 50이어도 하위 4비트가 같으면 같은 인덱스로 매핑

2. resize에서의 AND 연산: e.hash & oldCap

영향:

  • 해시 코드의 특정 비트(5번째 비트)만 확인
  • 이 비트 값에 따라 인덱스가 변경되거나 유지됨
  • 연결 리스트를 효율적으로 분할하여 성능 향상

전체적인 영향:

  • 하위 비트 의존성: AND 연산은 항상 하위 비트만 사용
  • 해시 분산의 중요성: 상위 비트 정보를 하위 비트에 반영해야 충돌 감소
  • resize의 효율성: 비트 확인만으로 재배치 가능 → 성능 최적화

⚠️ 핵심: resize에서 oldCap과의 AND 연산의 의미

멘토가 강조한 부분: resize에서 oldCap과 AND 연산하는 부분이 해시 코드에 어떤 영향을 미치는가?

e.hash & oldCap 연산의 목적:

  1. 효율적인 재배치: 모든 Node를 새로 계산하지 않고 비트 확인만으로 분할
  2. 연결 리스트 분할: 길이 감소로 성능 향상

해시 코드에 미치는 영향:

  • 해시 코드의 특정 비트(5번째 비트)만 확인
  • 이 비트가 0이면 기존 인덱스 유지, 1이면 새 인덱스로 이동
  • 핵심: 해시 코드의 나머지 비트는 무시됨 → 비트 하나만으로 분할 결정

예시:

기존 배열 크기: oldCap = 16
기존 인덱스: j = 6

연결 리스트:
  Node1 (hash = 134, 5번째 비트 0) → 새 인덱스 6
  Node2 (hash = 182, 5번째 비트 1) → 새 인덱스 22
  Node3 (hash = 150, 5번째 비트 0) → 새 인덱스 6

분할 결과:
  loHead → Node1, Node3 (인덱스 6 유지)
  hiHead → Node2 (인덱스 22로 이동)

새 배열:
  newTab[6] = loHead (Node1 → Node3)
  newTab[22] = hiHead (Node2)

⚠️ 핵심: 연결 리스트가 두 개로 분할되어 성능이 향상됩니다!

🎓 핵심 정리

1. ⚠️ putVal의 AND 연산

  • 인덱스 계산: (n - 1) & hash
  • 목적: 해시 코드를 배열 인덱스로 변환
  • 제약: 배열 크기는 2의 거듭제곱이어야 함

2. ⚠️ resize의 두 가지 AND 연산

  • 첫 번째: e.hash & oldCap → 5번째 비트 확인, 연결 리스트 분할
  • 두 번째: e.hash & (newCap - 1) → 새 인덱스 계산
  • 목적: 효율적인 재배치 및 연결 리스트 분할

3. ⚠️ AND 연산이 해시 코드에 미치는 영향

  • 하위 비트만 사용: 상위 비트는 무시됨
  • 해시 재분산: hash() 메서드로 상위 비트 정보 반영
  • 충돌 감소: 해시 분산 개선으로 성능 향상
