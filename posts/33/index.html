EST AI - Decision Tree

스무고개처럼 질문을 반복해 데이터를 나누는 의사결정나무의 구조와 지니 불순도, 사전 가지치기를 소개합니다. | 버섯 데이터로 독버섯을 분류하며 교차 검증, Graphviz 시각화, 특성 중요도를 확인합니다.

2025년 12월 10일 오후 02:07

📚 오늘의 학습 내용

오늘은 Decision Tree (의사결정나무) 알고리즘을 학습하고, 버섯 데이터셋을 활용하여 독버섯과 식용버섯을 분류하는 실습을 진행했습니다. Decision Tree의 작동 원리, 지니 불순도 (Gini Impurity), 사전 가지치기 (Pre-pruning), 교차 검증 (Cross Validation), 그리고 특성 중요도 (Feature Importance)에 대해 학습했습니다.

1️⃣ Decision Tree (의사결정나무)란?

개념

  • 스무고개 하듯이 질문을 하고, 예/아니오 답변을 반복하며 학습
  • 특정 기준(질문)에 따라 데이터를 구분하는 모델
  • 분류와 회귀에 모두 사용 가능

예시: 매, 펭귄, 돌고래, 곰을 구분하는 의사결정 게임

Decision Tree의 구조

  • Root Node (루트 노드): 트리의 최상단 노드 (첫 번째 질문)
  • Decision Node (결정 노드): 중간에 있는 노드 (질문을 하는 노드)
  • Leaf Node (리프 노드): 최종 결과를 나타내는 노드 (답변)
  • depth (깊이): 루트 노드부터 리프 노드까지의 거리
  • Sub Tree (서브 트리): 트리의 일부분

의사 결정 방향

→ 불순도가 낮아지는 방향으로 학습

💡 궁금해서 찾아본 내용: 지니 불순도 (Gini Impurity)

  • 결정 트리 모델의 노드 분할 기준
  • Decision Tree는 불순도가 낮아지는 방향으로 학습
  • 시각화 시 각 노드에서 지니 불순도를 표시할 수 있음 (impurity = True)

3️⃣ Decision Tree 하이퍼파라미터

사전 가지치기 (Pre-pruning)

트리의 크기를 사전에 제한하여 과대적합을 방지하는 기법

실습에서 사용한 하이퍼파라미터:

  • max_depth=3: 트리의 최대 깊이를 3으로 제한

4️⃣ Decision Tree 장단점

장점

  • 쉽다: 이해하기 쉽고 직관적이다
  • 직관적이다: 의사결정 과정을 시각적으로 확인 가능

단점

  • 과대적합이 발생하기 쉬움: 이를 극복하기 위해서 트리의 크기를 사전에 제한하는 튜닝이 필요 (사전 가지치기)

5️⃣ 실습: 버섯 데이터 분류

데이터셋 정보

  • 8124개의 버섯 종류 데이터
  • 22개의 입력 특성 (X): cap-shape, cap-surface, cap-color, bruises, odor, gill-attachment, gill-spacing, gill-size, gill-color, stalk-shape, stalk-root, stalk-surface-above-ring, stalk-surface-below-ring, stalk-color-above-ring, stalk-color-below-ring, veil-type, veil-color, ring-number, ring-type, spore-print-color, population, habitat
  • 1개의 정답 데이터 (y): poisonous (독버섯: p, 식용버섯: e)

데이터 특징:

  • 모든 컬럼이 문자열(object) 타입
  • 결측치 없음
  • scikit-learn 알고리즘은 문자열 값을 입력값으로 받지 않으므로 encoding 과정 필요

1. 문제와 정답으로 분리

X = data.drop(columns=['poisonous'], axis=1)  # axis=1은 열
y = data['poisonous']

2. 데이터 전처리: One-hot Encoding

Encoding 방식:

  1. Label Encoding: class들 간의 상하관계가 있는 경우에 사용
  2. One-hot Encoding:
    • 컬럼수가 굉장히 늘어난다
    • 값의 크고 작음에 의미가 없을 때 사용 (우선순위가 없을 때)
    • 각 범주(종류)만큼의 자릿수를 만들고 단 한 개의 1과 나머지 0으로 채워서 숫자화
X_one_hot = pd.get_dummies(X, dtype=int)
# 22개 컬럼 → 117개 컬럼으로 증가

3. Train/Test 데이터 분리

from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X_one_hot, y, 
    test_size=0.3, 
    random_state=2
)

# (5686, 117) (5686,)
# (2438, 117) (2438,)

4. 모델링

기본 모델 (하이퍼파라미터 조정 없음)

from sklearn.tree import DecisionTreeClassifier

# 모델 객체 생성
tree_model = DecisionTreeClassifier()

# 모델 학습
tree_model.fit(X_train, y_train)

# 모델 평가
print(tree_model.score(X_train, y_train))  # 1.0
print(tree_model.score(X_test, y_test))    # 1.0

결과 분석:

  • 모델 성능 평가가 매우 잘 나오는 독특한 데이터
  • 데이터 구분이 매우 쉬운 데이터
  • 특성을 보면 '냄새'에서 거의 구분됨

하이퍼파라미터 조절한 모델

tree_model_2 = DecisionTreeClassifier(max_depth=3)
tree_model_2.fit(X_train, y_train)

print(tree_model_2.score(X_train, y_train))  # 0.9857544846992613
print(tree_model_2.score(X_test, y_test))     # 0.9840032813781788

6️⃣ 교차 검증 (Cross Validation)

개념

학습-평가 데이터를 골고루 설정하여 모델의 안정성을 높이고 과대적합을 감소시키는 통계적 기법

K-fold Cross-validation 동작 방법

  1. Train 데이터를 k개의 그룹으로 나누기
  2. K-1개의 그룹을 학습에 사용
  3. 나머지 1개의 그룹을 이용해서 평가 수행
  4. 2번, 3번 과정을 k번 반복
  5. 모든 결과의 평균을 구하기

예시 (K=5):

  • 1번 세트를 test로, 나머지를 train으로 사용
  • 2번 세트를 test로, 나머지를 train으로 사용
  • ... (5번 반복)
  • 5개의 평가 결과의 평균 계산

교차 검증 장단점

장점:

  • 모든 데이터셋을 학습과 평가에 활용하기 때문에 안정적이고 정확함
  • 통계적 기법으로 과대적합을 감소시킴 (일반화에 도움이 됨)
  • 모델이 훈련 데이터의 변경에 대해 얼마나 민감한지 파악 가능
  • 데이터셋의 크기가 충분히 크지 않은 경우에도 유용하게 사용 가능

단점:

  • 여러 번 학습하고 평가하는 과정을 거치기 때문에 계산량이 많아짐

사용법

from sklearn.model_selection import cross_val_score

# cross_val_score(모델, X_train, y_train, cv=교차 검증 횟수)
scores = cross_val_score(tree_model, X_train, y_train, cv=5)
# array([1.        , 0.99912049, 1.        , 1.        , 1.        ])

scores_2 = cross_val_score(tree_model_2, X_train, y_train, cv=5)
# array([0.98594025, 0.98592788, 0.98416887, 0.98416887, 0.98592788])

참고: 교차 검증은 '성능 평가'만 해줌 (모델 학습은 하지 않음)

7️⃣ Decision Tree 시각화

Graphviz를 사용한 트리 시각화

필요한 라이브러리:

  • 시스템 레벨 Graphviz 바이너리 (brew install graphviz)
  • Python 패키지 python-graphviz (conda install python-graphviz)

Graphviz 설치 이슈:

  • macOS의 경우 시스템 레벨 Graphviz는 Homebrew로 설치: brew install graphviz
  • Python에서 import graphviz를 사용하려면 반드시 python-graphviz 패키지가 필요함
  • Windows의 경우 os.environ["PATH"] 설정이 필요할 수 있지만, macOS에서는 일반적으로 불필요함

시각화 코드

from sklearn.tree import export_graphviz
import graphviz

# DOT 파일로 내보내기
export_graphviz(
    tree_model,
    out_file='../data/tree_model.dot',
    class_names=['poisonous', 'edible'],
    feature_names=X_one_hot.columns,
    impurity=True,  # 각 노드에서 지니 불순도 표시 여부
    filled=True     # 각 노드들의 클래스가 구분되도록 색을 칠해주는 작업
)

# DOT 파일 읽기 및 시각화
with open('../data/tree_model.dot', encoding='utf-8') as f:
    dot_graph = f.read()

# 그래프 크기 조절 (size 값 조절: "8,6" -> "6,4" 등으로 줄이면 더 작아짐)
dot_graph = dot_graph.replace('digraph Tree {', 'digraph Tree {\ngraph [size="9,8!"];')

graphviz.Source(dot_graph)

참고:

  • 만약 class_names를 한글로 지정할 경우, 한글 인코딩 작업을 별도로 해줘야 함
  • tree_model_2 (max_depth=3)도 동일한 방식으로 시각화 가능

8️⃣ 특성 선택 (Feature Selection)

특성 중요도 (Feature Importance)

  • 각 특성들의 중요도를 출력 (지도학습에서 가능)
  • 정답에 얼마만큼의 영향을 미치는 특성인가를 수치로 확인 가능
  • 각 특성들의 중요도는 0~1 사이의 값을 가짐
  • 모든 특성의 중요도의 합은 1
  • tree 모델은 특성의 중요도가 높은 값을 상위 질문으로 배치한다

특성 중요도 확인

# 특성 중요도 추출
feature_importance = tree_model.feature_importances_

# DataFrame으로 변환 및 정렬
fi_df = pd.DataFrame(
    feature_importance, 
    index=X_one_hot.columns, 
    columns=['특성중요도']
).sort_values('특성중요도', ascending=False)

fi_df

결과 예시:

  • odor_n: 0.613250 (61.3%)
  • stalk-root_c: 0.179948 (18.0%)
  • stalk-surface-below-ring_y: 0.105063 (10.5%)
  • spore-print-color_r: 0.030150 (3.0%)
  • odor_a: 0.023094 (2.3%)
  • ...

분석 결과

  • tree 모델 내부 시각화 표를 보면, 중요도가 높은 특성 odor_n이 최상단 질문으로 배치되어 있음을 확인
  • 중요도가 가장 높은 특성을 먼저 고려해야 한다 (불순도가 낮아지는 방향으로 학습)
  • 현재 mushroom 데이터는 하나의 특성이 60%가 넘는 중요도를 가지고 있기 때문에, 모델 입장에서 학습이 용이했으며, 정확도도 높았음

💡 핵심 정리

배운 것

  • Decision Tree (의사결정나무): 스무고개 하듯이 질문을 반복하며 분류하는 모델
  • 지니 불순도 (Gini Impurity): 노드 내 클래스 혼합 정도를 측정하는 지표 (0~0.5)
  • Decision Tree 구조: Root Node, Decision Node, Leaf Node, depth, Sub Tree
  • 하이퍼파라미터: criterion, max_depth, min_samples_split, min_samples_leaf, max_leaf_nodes
  • 사전 가지치기 (Pre-pruning): 트리 크기를 사전에 제한하여 과대적합 방지
  • 교차 검증 (Cross Validation): 모든 데이터를 학습과 평가에 활용하여 모델 안정성 향상
  • 특성 중요도 (Feature Importance): 각 특성이 정답에 미치는 영향을 수치로 확인
  • One-hot Encoding: 범주형 데이터를 숫자로 변환하는 방법 (우선순위가 없을 때 사용)

인사이트

  • Decision Tree의 직관성: 의사결정 과정을 시각적으로 확인할 수 있어 이해하기 쉬움
  • 과대적합 제어의 중요성: 트리 크기를 제한하지 않으면 과대적합이 발생하기 쉬움
  • 특성 중요도의 활용: 어떤 특성이 예측에 중요한지 파악하여 데이터 수집 및 전처리 방향 설정 가능
  • 교차 검증의 필요성: 단일 train/test split보다 더 안정적인 모델 평가 가능

주의사항

  • ⚠️ Decision Tree는 과대적합이 발생하기 쉬움: 사전 가지치기 필수
  • ⚠️ One-hot Encoding은 컬럼 수가 크게 증가: 메모리 사용량 고려 필요
  • ⚠️ 교차 검증은 계산량이 많음: 데이터 크기와 모델 복잡도에 따라 시간 소요
