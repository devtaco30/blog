📚 오늘의 학습 내용

오늘은 선형 분류 모델을 학습하고, 직원의 이직 여부를 예측하는 실전 프로젝트를 진행했습니다. 데이터 전처리, 탐색적 데이터 분석(EDA), 가설 검증을 통해 이직률과 연관된 요인들을 분석했습니다.

1️⃣ 문제 정의

비즈니스 문제

  • BX (Business eXperience): 최근 이직 시장이 활발하게 성장함에 따라 직원들도 줄줄이 퇴사 행렬을 이어가고 있다. 경영진은 핵심인재 유출을 최대한 줄이고, 오랜시간 함께 성장할 수 있는 회사를 만들고 싶다.

  • CX (Customer eXperience): 자신의 성장을 느낄 수 있는 회사, 성과에 따른 적절한 보상과 효율적인 업무를 진행할 수 있는 회사

  • DX (Data eXperience): 데이터 분석을 통해 이직률과 연관이 있는 사항들을 지속적으로 확인하고 개선, HR팀은 이직 가능성이 높은 핵심 인재를 예측하고 해당 인원을 위한 관리 프로그램을 운영

2️⃣ 데이터 수집 및 전처리

데이터 개요

  • 데이터셋: job_transfer.csv
  • 데이터 크기: 1470명의 직원 데이터
  • 특성 수: 34개의 특성 (Feature)
  • 정답 데이터: 1개 (Attrition: 이직 여부)
  • 결측치: 없음

주요 컬럼

  • Attrition: 직원의 이직 여부 (Yes / No)
  • Age: 직원의 나이
  • Department: 부서 (Research & Development, Sales, Human Resources)
  • Gender: 성별 (Male, Female)
  • JobSatisfaction: 직무 만족도 (1~4)
  • RelationshipSatisfaction: 인간관계 만족도 (1~4)
  • OverTime: 초과 근무 여부 (Yes / No)
  • PercentSalaryHike: 급여 인상 비율
  • YearsAtCompany: 회사 근속 연수
  • YearsInCurrentRole: 현재 역할 근무 기간

데이터 전처리

1. 이직 여부 데이터 숫자 변환

# 학습 및 집계를 위하여 이직 데이터를 '숫자' 데이터로 변경
# 이직안함 -> 0, 이직 -> 1
data['Attrition'] = np.where(data['Attrition'] == 'Yes', 1, 0)

# np.where(조건식, True일 때, False일 때)

주의사항:

  • ⚠️ np.where()로 변환한 결과를 반드시 data['Attrition']에 할당해야 함
  • ❌ 할당하지 않으면 원본 데이터는 여전히 문자열 타입이어서 groupby().agg(['sum']) 시 오류 발생

2. 연령대 그룹화

# 나이 -> 연속적 숫자 형태로 되어 있음 -> 구간을 나눠서 그룹화
# 30세 이하 | 31~40세 | 40세 초과
data['Age_gp'] = np.where(
    data['Age'] <= 30, 
    '30세 이하', 
    np.where(data['Age'] <= 40, '31~40세', '40세 초과')
)

3️⃣ 탐색적 데이터 분석 (EDA)

기본 이직률 확인

  • 이직 안함 (No): 1233명 (83.9%)
  • 이직 (Yes): 237명 (16.1%)

연령대별 이직률

df_gp = data.groupby('Age_gp')['Attrition'].agg(['count', 'sum'])
df_gp['ratio'] = round((df_gp['sum'] / df_gp['count']) * 100, 1)

인사이트: 젊은 직원일수록 이직률이 높음

성별별 이직률

  • Female: 14.8% (588명 중 87명)
  • Male: 17.0% (882명 중 150명)

인사이트: 성별에 따른 이직률 차이는 크지 않음

부서별 이직률

  • Sales: 20.6% (446명 중 92명)

4️⃣ 가설 검증

가설 1: 업무만족도가 높더라도, 인간관계로 인한 이직률은 높을 것이다

업무만족도별 이직률

  • 만족도 1 (Low): 22.8%
  • 만족도 2: 16.4%
  • 만족도 3: 16.5%
  • 만족도 4 (Very High): 11.3%

인간관계만족도별 이직률

  • 만족도 1 (Low): 20.7%
  • 만족도 2: 14.9%
  • 만족도 3: 15.5%
  • 만족도 4 (Very High): 14.8%

업무만족도 × 인간관계만족도 교차 분석

df_gp = data.groupby(['JobSatisfaction', 'RelationshipSatisfaction'])['Attrition'].agg(['count', 'sum'])
df_gp['ratio'] = round((df_gp['sum'] / df_gp['count']) * 100, 1)

결론:

  • 업무만족도가 높을수록 인간관계로 인한 영향이 적다
  • 업무만족도가 낮을수록 인간관계에 영향이 높다
  • 권장사항: 업무만족도가 낮은 인원들에게는 인간관계 프로그램 추천

가설 2: 근속년수 대비 같은 업무를 한 비중이 높다면 이직률이 높을 것이다

RoleCompany 비율 계산

# 근속년수 대비 한 가지 업무에서 진행 비율
data['RoleCompany'] = data['YearsInCurrentRole'] / data['YearsAtCompany']
# 결측치 0으로 채우기 (0년차니까)
data['RoleCompany'].fillna(0, inplace=True)

RoleCompany 구간화

# 0.3 이하, 0.3 초과 0.6 이하, 0.6 초과
data['RoleCompany_gp'] = np.where(
    data['RoleCompany'] <= 0.3, 
    '0.3 이하', 
    np.where(data['RoleCompany'] <= 0.6, '0.3 초과 0.6 이하', '0.6 초과')
)

결과:

  • 0.3 이하: 27.6% (323명 중 89명)
  • 0.3 초과 0.6 이하: 11.8% (321명 중 38명)
  • 0.6 초과: 13.3% (826명 중 110명)

결론: 가설이 맞음. 같은 업무를 오래 한 직원(0.3 이하)의 이직률이 가장 높음

가설 3: 야근을 많이 해도 급여인상률이 높다면 이직률이 낮을 것이다

야근 여부별 이직률

  • No: 10.4% (1054명 중 110명)
  • Yes: 30.5% (416명 중 127명)

야근 여부 × 급여인상률 교차 분석

df_gp = data.groupby(['OverTime', 'PercentSalaryHike'])['Attrition'].agg(['count', 'sum'])
df_gp['ratio'] = round((df_gp['sum'] / df_gp['count']) * 100, 1)

결과:

  • 야근 No + 급여인상률 높음: 평균 이직률 약 9.4%
  • 야근 Yes + 급여인상률 높음: 여전히 높은 이직률 (20~55%)

결론:

  • 야근을 많이 하는 사람들은 높은 연봉 인상에도 불구하고 이직률이 크게 낮아지지 않는다
  • 급여인상만으로는 야근으로 인한 이직을 막기 어려움

5️⃣ 모델링 준비

데이터 분리

# 가설 검증을 위해 생성했던 컬럼 삭제
X = data.drop(['Attrition', 'Age_gp', 'RoleCompany_gp', 'OverTime'], axis=1)
y = data['Attrition']

레이블 인코딩 (Label Encoding)

레이블 인코딩이란?

  • 값의 크고 작음의 의미가 있을 때 사용
  • 순서가 있는 범주형 데이터에 적합
  • 예: 출장 빈도 (Non-Travel < Travel_Rarely < Travel_Frequently)

BusinessTravel 레이블 인코딩

# Dictionary로 정의 (우선순위를 주고 싶은 데이터에 큰 숫자를 연결)
BT_dict = {
    'Non-Travel': 1,
    'Travel_Rarely': 2,
    'Travel_Frequently': 3
}

# map() 함수로 매핑
# map(): 값을 매핑, key 값을 찾아서 해당 value 값으로 변경
X['BusinessTravel'] = X['BusinessTravel'].map(BT_dict)

레이블 인코딩 vs 원-핫 인코딩:

  • 레이블 인코딩: 순서가 있는 범주형 데이터 (예: 출장 빈도, 만족도)
  • 원-핫 인코딩: 순서가 없는 범주형 데이터 (예: 부서, 성별)

원-핫 인코딩 (One-Hot Encoding)

# 나머지 컬럼들 One-Hot encoding 진행
X_one_hot = pd.get_dummies(X, dtype=int)

원-핫 인코딩이란?

  • 순서가 없는 범주형 데이터를 0과 1로 표현하는 방법
  • 각 카테고리를 독립적인 이진 특성으로 변환
  • 예: 부서가 3개면 3개의 컬럼 생성 (각 부서별로 0 또는 1)

모델 1: Logistic Regression

모델 학습

from sklearn.linear_model import LogisticRegression

lr_model = LogisticRegression(max_iter=5000)
lr_model.fit(X_train, y_train)

주의사항:

  • ⚠️ max_iter=5000 설정 필요: 최적값을 찾지 못할 경우 반복 횟수 증가
  • 분류 모델이므로 score()는 **정확도(Accuracy)**를 반환 (R²가 아님)

모델 성능

  • Train Accuracy: 87.5%
  • Test Accuracy: 84.8%

교차검증 (Cross Validation)

교차검증이란?

  • 모델의 일반화 성능을 측정하는 방법
  • 한 번 평가하는 것이 아닌 여러 번에 걸쳐 평가하여 신뢰도 향상
  • 훈련 데이터 내에서 훈련세트와 테스트 세트로 나눠 여러 번 평가

교차검증의 장단점

장점:

  • 과적합을 감소하는데 도움이 됨
  • 모델이 훈련데이터의 변경에 얼마나 민감한지 확인 가능
  • 데이터셋이 적은 경우 유용하게 사용됨

단점:

  • 여러 번 학습하고 평가 → 계산량이 많아지고 시간, 비용 많이 듦

K-Fold 교차검증 구현

from sklearn.model_selection import cross_val_score

# 5-Fold 교차검증
cv_scores = cross_val_score(lr_model, X_train, y_train, cv=5)
# 결과: [0.869, 0.869, 0.845, 0.874, 0.859]

# 평균 성능
cv_scores.mean()  # 0.863 (86.3%)

결과 해석:

  • 5번의 교차검증 결과 평균 정확도: 86.3%
  • 각 Fold별 성능이 비슷하면 모델이 안정적임을 의미

모델 2: Linear SVC (Support Vector Machine)

모델 학습

from sklearn.svm import LinearSVC

svm_model = LinearSVC()
svm_model.fit(X_train, y_train)

# 교차검증
svm_cv_scores = cross_val_score(svm_model, X_train, y_train, cv=5)
svm_cv_scores.mean()  # 0.858 (85.8%)

모델 성능

  • Cross Validation 평균: 85.8%
  • Test Accuracy: 85.3%

LinearSVC란?

  • Support Vector Machine의 선형 버전
  • 데이터를 나누는 직선을 그어서 클래스를 나눔
  • 선형 분류 문제에 적합

모델 평가: Classification Report

분류 평가 지표

from sklearn.metrics import classification_report

predict = svm_model.predict(X_test)
print(classification_report(y_test, predict))

결과:

              precision    recall  f1-score   support

           0       0.86      0.98      0.92       367
           1       0.71      0.20      0.32        74

    accuracy                           0.85       441
   macro avg       0.79      0.59      0.62       441
weighted avg       0.84      0.85      0.82       441

평가 지표 설명

1. Precision (정밀도)

  • 모델이 양성으로 예측한 것 중 실제로 양성인 비율
  • TP / (TP + FP)
  • 해석: "이직할 것이라고 예측한 직원 중 실제로 이직한 비율"

2. Recall (재현율)

  • 실제 양성 중 모델이 양성으로 예측한 비율
  • TP / (TP + FN)
  • 해석: "실제로 이직한 직원 중 모델이 찾아낸 비율"

3. F1-Score

  • Precision과 Recall의 조화평균
  • 2 * (Precision * Recall) / (Precision + Recall)
  • 두 지표의 균형을 나타냄

4. Support

  • 각 클래스의 실제 샘플 수
  • Class 0: 367개, Class 1: 74개

Confusion Matrix 개념

TP (True Positive): 실제 이직, 예측 이직 ✅ FP (False Positive): 실제 재직, 예측 이직 ❌

  • 회사 계속 다닐 직원을 이직할 거라고 착각

FN (False Negative): 실제 이직, 예측 재직 ❌

  • 이직 마음먹을 사원을 안한다고 착각 → 위험하다!

TN (True Negative): 실제 재직, 예측 재직 ✅

결과 해석

Class 0 (퇴사 안함):

  • Precision: 0.86, Recall: 0.98
  • 잘 예측하고 있음 ✅

Class 1 (이직 함):

  • Precision: 0.71, Recall: 0.20
  • 정밀도는 높지만 재현율이 매우 낮음 ⚠️
  • 실제 이직할 직원의 80%를 놓치고 있음

비즈니스 관점:

  • FN (False Negative)가 더 위험: 이직할 직원을 놓치는 것
  • 따라서 재현율(Recall)이 더 중요함
  • 현재 모델은 재현율이 낮아 개선이 필요함

  • 가설 검증을 통한 데이터 인사이트 도출
  • 레이블 인코딩과 원-핫 인코딩의 개념과 적용 방법

  • **교차검증(Cross Validation)**을 통한 모델 일반화 성능 측정

인사이트

  • 연령대: 젊은 직원일수록 이직률이 높음 (30세 이하: 25.9%)
  • 업무만족도: 업무만족도가 낮을수록 인간관계의 영향이 큼
  • 직무 다양성: 같은 업무를 오래 한 직원의 이직률이 높음 (27.6%)
  • 야근과 급여: 급여인상만으로는 야근으로 인한 이직을 막기 어려움

주의사항

  • ⚠️ 데이터 변환 시 할당 필수: np.where() 결과를 반드시 변수에 할당해야 함
  • ⚠️ 데이터 타입 확인: 문자열 데이터에 sum() 연산 시 오류 발생 가능
  • ✅ 레이블 인코딩 선택: 순서가 있는 범주형 데이터에만 사용
  • ✅ 가설 검증: 단순 집계뿐만 아니라 교차 분석을 통해 깊이 있는 인사이트 도출
  • ⚠️ LogisticRegression max_iter: 최적값을 찾지 못할 경우 max_iter 파라미터 증가 필요
  • ⚠️ 분류 모델의 score(): 회귀 모델과 달리 정확도(Accuracy)를 반환 (R² 아님)
  • ✅ 교차검증 활용: 단일 train/test 분리보다 교차검증이 모델의 일반화 성능을 더 정확히 평가
