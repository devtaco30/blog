📚 오늘의 학습 내용

오늘은 BERTopic을 활용한 통합 텍스트 마이닝 파이프라인을 학습했습니다. 한국어 SNS 대화 데이터를 사용하여 요약 → 임베딩 → 클러스터링 → 감성 분석까지 전체 과정을 사전 학습 모델만으로 구현하는 방법을 익혔습니다.

1️⃣ 학습 시나리오

가상 시나리오 설정

상황:

  • 월간 50만 건 이상의 SNS 대화를 처리하는 기업용 분석 플랫폼 'K-인사이트' 개발
  • AI Hub의 한국어 SNS 데이터('미용과 건강', '식음료', '일과 직업')를 활용

문제:

  • 긴 대화 로그에 메타정보, 반복, 발화, 잡음이 포함되어 핵심 주제 파악 어려움
  • 실시간 감성 분석과 토픽 모니터링 필요

학습 목표:

  • 요약 → 임베딩 → 클러스터링 → 감성 분석의 통합 파이프라인 구현 방법 학습
  • 사전 학습 모델만 활용한 효율적인 분석 시스템 구축 경험

데이터셋

AI Hub - 한국어 SNS 데이터셋

  • 출처: https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71694
  • 형식: JSON (메타정보 + 발화 리스트)
  • 사용 카테고리: 미용과 건강, 식음료, 일과 직업
  • 각 카테고리당 200개 대화 샘플링 (총 600개)

2️⃣ 데이터 준비 및 전처리

데이터 로드 함수 구현

주요 개념:

def load_and_normalize(path):
    corpus = []
    
    for fname in tqdm(sorted(os.listdir(path)), desc=f'Loading data from {path}'):
        file_path = os.path.join(path, fname)  # ⚠️ path 변수 덮어쓰기 주의!
        count = 0
        
        with open(file_path, 'r', encoding='utf-8') as f:
            dataset = json.load(f)
        
        for dialogue in tqdm(dataset['data'], desc=f'Processing {fname}'):
            # 라벨당 제한 (limit_per_label)
            if count >= limit_per_label:
                break
            
            # 대화의 모든 발화를 하나의 문자열로 결합
            text = ' '.join([utterance['utterance'] for utterance in dialogue['body']])
            corpus.append(text)
            count += 1
            
    return corpus

주의 사항:

  • 변수명 충돌 주의: path 파라미터를 덮어쓰지 않도록 file_path 사용
  • 각 파일에서 200개씩, 총 600개의 대화가 하나의 corpus에 통합됨

3️⃣ 대화 요약 (Summarization)

요약이 필요한 이유

  1. 문서 길이 절감: 핵심 내용만 남겨 연산 속도 향상
  2. 노이즈 제거: 불필요한 대화(인사, 중복) 압축
  3. 토픽 명확화: BERTopic이 더 뚜렷한 주제어 학습 가능

KoT5 요약 모델

모델 정보:

  • Hugging Face: psyche/KoT5-summarization
  • T5 (Text-to-Text Transfer Transformer) 기반 한국어 요약 모델
  • 입력: 최대 512 토큰
  • 출력: 최대 256 토큰 (설정 가능)

사전 학습:

  • 코퍼스: 위키백과, 신문기사 등 23개 출처 (총 42GB)
  • WordPiece 토크나이저 사용

파인튜닝:

  • 데이터: AI-Hub '도서자료 요약' 데이터셋
  • 디코딩: Greedy decoding
  • Repetition penalty: 2.0 (반복 억제)

⚠️ 중요: Tokenizer와 Device 관계

# ============================================================
# [중요] Tokenizer와 Device 관계
# ============================================================
# 
# 1. 모델의 device 이동
#    - model.to(device) 호출 시 모델의 모든 파라미터가 해당 device로 이동
#    - 예: model.to('mps') → 모델이 Apple GPU 메모리에 적재
#
# 2. Tokenizer의 특성
#    - Tokenizer는 PyTorch 모델(nn.Module)이 아닌 단순 텍스트 전처리 도구
#    - return_tensors='pt'를 사용해도 항상 CPU 텐서를 반환
#    - device 설정과 무관하게 작동 (device 개념이 없음)
#
# 3. Device 불일치 문제
#    - 모델: MPS/CUDA에 위치
#    - 입력: CPU에 위치
#    - → RuntimeError 발생 (다른 메모리 공간에서 연산 불가)
#
# 4. 해결 방법
#    - tokenizer 출력을 명시적으로 device로 이동
#    - inputs = tokenizer(...).to(device)
#
# 5. 핵심
#    - Tokenizer는 device를 인식하지 못함
#    - 개발자가 직접 .to(device)로 이동 필수
# ============================================================

모델 로드:

from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

# 토크나이저 로드
tokenizer = AutoTokenizer.from_pretrained('psyche/KoT5-summarization')

# 모델 로드 및 device 이동
model = AutoModelForSeq2SeqLM.from_pretrained('psyche/KoT5-summarization').to(device)

요약 함수 구현

def summarize_text(text):
    # 입력 토큰화 및 device 이동
    inputs = tokenizer(
        text,
        return_tensors='pt',  # PyTorch 텐서 형태로 반환
        truncation=True,  # 최대 길이 초과 시 자동 잘라냄
        max_length=512  # 입력 토큰의 최대 길이
    ).to(device)  # ⚠️ 반드시 device로 이동!
    
    # 요약문 생성
    outputs = model.generate(
        **inputs,  # tokenizer가 반환한 dict 형태로 전달
        max_length=100,  # 요약문의 최대 토큰 길이
        min_length=20,  # 요약문의 최소 토큰 길이
        num_beams=4,  # beam search 수: 4개 후보 유지
        early_stopping=True,  # EOS 토큰 만나면 즉시 생성 멈춤
        length_penalty=2.0  # 값>1.0: 긴 요약 선호, 값<1.0: 짧은 요약 선호
    )
    
    # 디코딩 및 반환
    summary = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return summary

파라미터 설명:

  • num_beams: Beam Search의 빔 개수

    • 매 단계에서 가장 가능성 높은 N개 후보를 유지하며 탐색
    • 값이 클수록 품질 향상, 속도 감소

  • length_penalty: 길이 가중치

    • 값 > 1.0: 긴 문장 선호
    • 값 = 1.0: 중립
    • 값 < 1.0: 짧은 문장 선호

전체 코퍼스 요약

# Train 샘플 요약
summaries = [summarize_text(doc) for doc in tqdm(train_corpus, desc='Summarizing')]

print(f'원본: {train_corpus[0][:100]}...')
print(f'요약: {summaries[0]}')

4️⃣ 문장 임베딩 (Sentence Embedding)

Sentence-BERT (SBERT)

개념:

  • 문장 전체를 하나의 벡터로 표현
  • 의미적으로 유사한 문장들이 벡터 공간에서 가까이 위치
  • 문장 간 유사도 계산 및 클러스터링에 활용

일반 BERT vs SBERT:

구분일반 BERTSBERT
출력토큰별 벡터문장 하나당 벡터 1개
용도토큰 분류, 질의응답문장 유사도, 클러스터링
Pooling없음Average Pooling

KR-SBERT 모델

모델 정보:

  • Hugging Face: snunlp/KR-SBERT-V40K-klueNLI-augSTS
  • 한국어 특화 Sentence-BERT
  • 출력: 768차원 밀집 벡터

사전 학습:

  • KR-BERT-V40K (WordPiece 토크나이저)
  • Average Pooling으로 문장 벡터 생성

Average Pooling 과정:

문장: "나는 밥을 먹었다"
토큰: [나는] [밥을] [먹었다]

각 토큰의 벡터:
[나는]   → [0.1, 0.2, 0.3, ...]
[밥을]   → [0.4, 0.5, 0.6, ...]
[먹었다] → [0.7, 0.8, 0.9, ...]

Average Pooling (평균):
→ [(0.1+0.4+0.7)/3, (0.2+0.5+0.8)/3, ...]
→ 문장 하나 = 벡터 하나 (768차원)

Siamese 네트워크 구조

파인튜닝 방법:

입력: 문장 A, 문장 B

1. 두 문장을 동일한 BERT 모델(가중치 공유)에 통과
   문장 A → SBERT → 벡터 A (768차원)
   문장 B → SBERT → 벡터 B (768차원)

2. 두 벡터 간 거리 계산
   Distance = ||벡터 A - 벡터 B||

3. 분류기로 유사도 판단
   Probability = sigmoid(Distance)

학습 목표:
- 비슷한 문장 → 벡터 거리 작게
- 다른 문장 → 벡터 거리 크게

학습 데이터:

  • KLUE-NLI (한국어 자연어 추론)
  • KorSTS (한국어 의미 유사도)
  • in-domain 증강 전략: 한국어 문체 다양화

Siamese 네트워크의 핵심:

구조:
Input 1, Input 2 → Siamese Subnetwork (가중치 공유)
                 → Embedding 1, Embedding 2
                 → Distance 계산
                 → Probability (같은 클래스일 확률)

결과:
- 같은 클래스끼리는 모이고
- 다른 클래스끼리는 멀어짐

임베딩 모델 사용

from sentence_transformers import SentenceTransformer

# 모델 로드

# 요약문을 벡터로 변환

# shape: (600, 768)

5️⃣ BERTopic을 이용한 토픽 모델링

BERTopic이란?

개념:

  • BERT 기반 토픽 모델링 기법
  • 클러스터링과 TF-IDF를 결합하여 주제 추출
  • 사전 학습 임베딩을 활용하여 의미적 주제 파악

전통적 LDA vs BERTopic:

구분LDABERTopic
임베딩Bag of WordsBERT 임베딩
클러스터링확률 기반HDBSCAN
주제 표현단어 분포TF-IDF 키워드
의미 파악단어 동시 출현문맥 이해

BERTopic 파이프라인

from bertopic import BERTopic
from umap import UMAP
from hdbscan import HDBSCAN
from sklearn.feature_extraction.text import CountVectorizer

# UMAP: 차원 축소 (768차원 → 5차원)
umap_model = UMAP(
    n_neighbors=15,
    n_components=5,
    min_dist=0.0,
    metric='cosine'
)

# HDBSCAN: 밀도 기반 클러스터링
hdbscan_model = HDBSCAN(
    min_cluster_size=10,
    metric='euclidean',
    cluster_selection_method='eom'
)

# CountVectorizer: 한국어 토큰화
vectorizer_model = CountVectorizer(stop_words=['은', '는', '이', '가'])

# BERTopic 모델 생성
topic_model = BERTopic(
    embedding_model=embedding_model,
    umap_model=umap_model,
    hdbscan_model=hdbscan_model,
    vectorizer_model=vectorizer_model,
    language='korean',
    verbose=True
)

# 토픽 추출
topics, probs = topic_model.fit_transform(summaries)

6️⃣ 감성 분석 (Sentiment Analysis)

한국어 감성 분석 모델

from transformers import pipeline

# 감성 분석 파이프라인
sentiment_analyzer = pipeline(
    "sentiment-analysis",
    model="beomi/kcbert-base"
)

# 토픽별 감성 분석
for topic_id in range(len(topic_model.get_topic_info())):
    # 해당 토픽에 속한 문서들
    docs_in_topic = [summaries[i] for i, t in enumerate(topics) if t == topic_id]
    
    # 감성 분석
    sentiments = sentiment_analyzer(docs_in_topic[:10])
    
    print(f"Topic {topic_id}:")
    for doc, sent in zip(docs_in_topic[:3], sentiments[:3]):
        print(f"  {doc[:50]}... → {sent['label']} ({sent['score']:.2f})")
