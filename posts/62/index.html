📚 오늘의 학습 내용

오늘은 YOLO를 활용해 객체 탐지 모델 직접 학습, 이미지 세그멘테이션, 영상 트래킹까지 세 가지 태스크를 실습했습니다.

1️⃣ 객체 탐지 데이터셋 구조

분류(Classification) vs 탐지(Detection) 데이터 비교

구분이미지 분류객체 탐지
핵심 질문"이 사진은 무엇인가?""어디에 무엇이 있는가?"
데이터 준비클래스명 폴더로 구분이미지 + 좌표 라벨 파일(.txt) 필수
YOLO 모델yolo11n-cls.ptyolo11n.pt
출력클래스 이름 + 확률바운딩 박스 시각화

YOLO 탐지 데이터 폴더 구조

dataset/
├── data.yaml          ← 클래스 목록, 경로 정의
├── images/
│   ├── train/
│   └── val/
└── labels/
    ├── train/
    └── val/

이미지 파일과 동일한 이름의 .txt 라벨 파일이 쌍으로 존재해야 한다. 객체가 없는 이미지는 라벨 파일을 만들지 않으면 됨.

바운딩 박스 좌표 형식

YOLO는 픽셀 좌표 대신 이미지 크기 대비 비율(0~1)로 정규화된 좌표를 사용한다.

라벨 파일 한 줄 형식: [클래스번호] [중심x] [중심y] [너비] [높이]

예시 — 이미지 1000×800px, 객체 중심 (500, 300)px, 박스 200×100px:

항목계산결과
중심 x500 / 10000.5
중심 y300 / 8000.375
너비200 / 10000.2
높이100 / 8000.125

→ 라벨 파일에 저장: 0 0.5 0.375 0.2 0.125

💡 정규화 덕분에 이미지 크기나 비율이 달라져도 객체의 상대적 위치가 그대로 유지됨

Roboflow

이미지를 업로드하고 웹에서 직접 바운딩 박스/마스크를 그려 라벨링할 수 있는 플랫폼. 라벨링 완료 후 YOLO 포맷으로 바로 다운로드할 수 있어 탐지 모델 실습에 많이 활용됨.

실습: 동물 탐지 모델 (cat / dog)

  • 데이터: Roboflow에서 cat/dog 2클래스 탐지 데이터셋 다운로드
  • 모델: yolo11n-seg.pt (탐지+세그멘테이션 겸용)
model = YOLO('yolo11n-seg.pt')
model.train(data='./animals-1/data.yaml', epochs=100, imgsz=512, patience=45, device='mps')

검증 결과 (valid set, 60장)

2️⃣ Image Segmentation

개념

객체 탐지가 "어디에 무엇이 있는가"를 박스로 나타낸다면, 세그멘테이션은 픽셀 단위로 "어느 픽셀이 어떤 객체에 속하는가"를 구분한다.

종류

종류설명예시
Semantic Segmentation픽셀을 카테고리로 분류, 같은 카테고리의 여러 객체는 구분 안 함자동차 3대 → 모두 "자동차" 영역
Instance Segmentation같은 카테고리도 각 객체를 개별적으로 구분자동차 3대 → "자동차1", "자동차2", "자동차3"

YOLO의 -seg 모델이 Instance Segmentation을 수행함.

활용 분야

  • 자율주행: 도로, 차선, 보행자, 신호등을 픽셀 단위로 구분
  • 의료 영상: MRI/CT에서 종양·장기 경계를 정확히 추출
  • 위성 이미지: 숲, 강, 도시 등 지형 자동 분류
  • 영상통화 배경 제거: 사람과 배경을 정교하게 분리

실습: 차량 파손 범위 예측

  • 데이터: Roboflow car 데이터셋 (14개 파손 클래스 — door_damage, glass_damage, scratch 등)
  • 모델: yolo11m-seg.pt (medium 크기, 세그멘테이션)
model = YOLO('yolo11m-seg.pt')
model.train(data='./car-1/data.yaml', epochs=100, imgsz=512, patience=25, device='mps')

예측 결과 — 차량 유리 파손 이미지 1장:

1 fender_damage, 1 front_bumper_damage, 2 glass_damages 검출

3️⃣ Object Tracking

개념

객체 탐지가 단일 프레임에서 "어디에 무엇이 있는가"를 찾는다면, 트래킹은 연속 프레임(영상) 에서 "같은 객체를 시간 흐름에 따라 추적"한다.

각 객체에 고유 ID가 부여되어, 프레임이 바뀌어도 동일 객체면 같은 ID를 유지함.

Ultralytics Tracking

model = YOLO('yolo11s.pt')

results = model.track(
    source='video.mp4',
    conf=0.3,   # 신뢰도 임계값 — 이 값 이상인 검출만 처리
    iou=0.5,    # NMS 겹침 임계값 — 0.5 이상이면 중복으로 판단해 제거
    save=True,
    stream=True,   # 메모리 효율 모드
    device='mps'
)

stream 파라미터

값동작 방식사용 상황
stream=False모든 프레임 결과를 한 번에 메모리에 적재짧은 영상, 결과 전체를 리스트로 다뤄야 할 때
stream=True프레임 단위로 처리 후 즉시 메모리 해제 (Generator)긴 영상, 메모리 부족 방지

⚠️ stream=True는 한 번 소비한 결과가 메모리에서 제거되므로, 필요한 데이터는 루프 안에서 바로 복사해야 함

Boxes 결과 객체 주요 속성

트래킹 결과의 result.boxes에서 꺼낼 수 있는 정보:

속성설명
cls클래스 번호 (15=cat, 16=dog ...)
conf신뢰도 (0~1)
id트래킹 ID — 프레임이 바뀌어도 같은 객체면 동일 ID
xyxy바운딩 박스 [좌상단x, 좌상단y, 우하단x, 우하단y] (픽셀)
xywh바운딩 박스 [중심x, 중심y, 너비, 높이] (픽셀)
xyxyn / xywhn정규화된 좌표 (0~1)

📝 요약

배운 것

  • 탐지 데이터 형식: 이미지와 짝을 이루는 .txt 라벨 (정규화 좌표), data.yaml로 경로·클래스 정의
  • Roboflow: 웹 기반 라벨링 → YOLO 포맷 바로 다운로드
  • Segmentation: -seg 모델로 박스 대신 픽셀 단위 마스크 생성; Semantic(카테고리) vs Instance(개별 객체) 구분
  • Tracking: model.track()으로 영상 속 객체에 ID 부여, 이동 경로 추적

주의사항

  • ⚠️ 탐지 라벨 좌표는 정규화 비율(0~1) — 픽셀값 그대로 쓰면 안 됨
  • ⚠️ stream=True는 Generator이므로 결과를 루프 밖에서 재사용 불가 — 루프 안에서 즉시 저장
  • ✅ 긴 영상 트래킹에는 반드시 stream=True로 OOM 방지
