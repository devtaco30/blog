[6년차 쯤 되면 좀 알자] Application 이 실행될 때 JVM 에선 어떤일이 일어날까?

예제 코드를 한 줄씩 따라가며 JVM이 클래스를 언제 로드하고 static 변수와 인스턴스 변수를 어디에 두는지 확인합니다. | 상속 관계에서 객체가 만들어질 때의 초기화 순서와 String Constant Pool도 이어집니다.

안녕하세요. Java/Kotlin 백엔드 개발자로서 JVM의 클래스 로딩 과정과 메모리 구조를 이해하는 것은 성능 최적화와 문제 해결에 필수적입니다.

본 포스팅에서는 실제 Java 코드 예제를 바탕으로, JVM이 클래스를 어떻게 로드하고, 메모리를 어떻게 할당하며, 객체가 생성되는 과정에서 어떤 일이 일어나는지 단계별로 상세하게 분석해보겠습니다.

📝 예제 코드

분석할 코드는 다음과 같습니다:

class A {
    private static final String STR = "ABC";
    private static Long l = Long.valueOf(-1L);
    private static int i = -1;
    private static C c = new C();
  
    private final String a = "ABC";
    private final int ii = 1;
    private C cc = new C();
  
    public static void main(String[] args) {
      // JVM Memory에서 무슨 일이 일어나는지 설명해 봅시다.
      A a = new A();
      B b = new B();
    }
  }
  
  class B extends A {
    // ...
  }
  
  class C {
    // ...
  }

이 코드를 실행하면 JVM 내부에서 어떤 일이 일어날까요? 단계별로 살펴보겠습니다.

🚀 1단계: 프로그램 실행 시작 (java A.java)

JVM 시작 및 Class Loader 초기화

프로그램이 시작되면 JVM이 초기화되고, 클래스 로더들이 순차적으로 초기화됩니다:

┌─────────────────────────────────────┐
│  JVM 시작 과정                       │
├─────────────────────────────────────┤
│  1. JVM 시작                         │
│  2. Bootstrap Class Loader 초기화    │
│  3. Extension Class Loader 초기화    │
│  4. Application Class Loader 초기화  │
└─────────────────────────────────────┘

초기 메모리 상태:

┌─────────────────────────────────────┐
│  메모리 영역 초기 상태                │
├─────────────────────────────────────┤
│  Method Area:  비어있음              │
│  Heap:         비어있음              │
│  Stack:        비어있음              │
└─────────────────────────────────────┘

📦 2단계: A 클래스 로드 (Lazy Loading)

⚠️ 핵심 포인트: Lazy Loading

JVM의 클래스 로딩은 Lazy Loading 방식입니다!

  • 프로그램 시작 시 모든 클래스를 로드하지 않음
  • 클래스가 처음 사용될 때만 로드됨
  • 메모리 효율성과 시작 시간 단축에 유리

2-1. main 메서드 발견 → A 클래스 로드 필요

JVM은 main 메서드를 찾기 위해 A 클래스를 로드해야 합니다. JVM의 클래스 로딩은 Lazy Loading 방식으로, 클래스가 처음 사용될 때만 로드됩니다.

JVM이 main 메서드를 찾기 위해 A 클래스 로드 시작
  ↓
Application Class Loader가 A.class 파일을 읽음
  ↓
A 클래스 정보를 Method Area에 로드

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스 메타데이터                 │
│  - 클래스 이름: A                    │
│  - 부모 클래스: Object               │
│  - 메서드 정보: main(String[])       │
│                                     │
│  A 클래스의 static 변수 선언 공간    │
│  - STR: null (아직 초기화 안됨)      │
│  - l:   null                        │
│  - i:   0 (기본값)                  │
│  - c:   null                        │
└─────────────────────────────────────┘

2-2. Static 변수 초기화 (선언 순서대로)

⚠️ 중요: Static 변수는 선언된 순서대로 초기화됩니다!

클래스가 로드되면 static 변수들이 선언된 순서대로 초기화됩니다.

2-2-1. private static final String STR = "ABC";

String 리터럴은 String Constant Pool에 저장됩니다!

1. "ABC" 리터럴이 String Constant Pool에 있는지 확인
   ↓
2. 없으면 String Constant Pool (Heap 내부)에 "ABC" 객체 생성
   ↓
3. Method Area의 STR 변수에 주소값 저장

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스                            │
│  - STR: → [주소값]                   │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap (String Constant Pool)         │
├─────────────────────────────────────┤
│  "ABC" String 객체                  │
└─────────────────────────────────────┘

주소 관계:

Method Area (STR 변수) → Heap (String Constant Pool의 "ABC" 객체)

2-2-2. private static Long l = Long.valueOf(-1L);

⚠️ Long 타입은 캐시를 확인합니다!

Long.valueOf() 메서드는 -128 ~ 127 범위의 값만 캐시합니다. 이는 String Constant Pool과 비슷하지만 범위가 제한적입니다.

Wrapper Class 캐시 정책:

Java의 모든 Wrapper Class들이 캐시를 사용하는 것은 아닙니다:

Wrapper Class캐시 범위비고
Byte-128 ~ 127모든 값이 캐시 범위 내
Short-128 ~ 127
Integer-128 ~ 127기본값, -XX:AutoBoxCacheMax=<size>로 변경 가능
Long-128 ~ 127
Character0 ~ 127유니코드 기본 영역 (ASCII)
Booleantrue, false두 개만 캐시
Float❌ 캐시 없음
Double❌ 캐시 없음

Long 캐시 vs String Constant Pool:

구분String Constant PoolWrapper Class 캐시
범위모든 String 리터럴제한적 범위만
위치Heap 내부Heap 내부
목적메모리 효율성 (모든 리터럴 공유)메모리 효율성 (자주 쓰는 값만 공유)
적용 타입String만Byte, Short, Integer, Long, Character, Boolean

Long.valueOf() 동작 방식:

1. Long.valueOf(-1L) 호출
   ↓
2. 값이 -128 ~ 127 범위인지 확인
   ↓
3-1. 범위 내: 캐시된 Long 객체 반환 (재사용)
3-2. 범위 밖: 새로운 Long 객체 생성
   ↓
4. Method Area의 l 변수에 주소값 저장

예시:

// Long 캐시
Long l1 = Long.valueOf(100L);   // 캐시 범위 내 → 캐시된 객체
Long l2 = Long.valueOf(100L);   // 캐시 범위 내 → 같은 객체
Long l3 = Long.valueOf(1000L); // 캐시 범위 밖 → 새 객체
Long l4 = Long.valueOf(1000L); // 캐시 범위 밖 → 또 다른 새 객체
l1 == l2;  // true (같은 객체)
l3 == l4;  // false (다른 객체)

// Integer 캐시
Integer i1 = Integer.valueOf(100);  // 캐시 범위 내
Integer i2 = Integer.valueOf(100);  // 같은 객체
Integer i3 = Integer.valueOf(1000); // 캐시 범위 밖
Integer i4 = Integer.valueOf(1000); // 다른 객체
i1 == i2;  // true
i3 == i4;  // false

// Character 캐시
Character c1 = Character.valueOf('A');  // 0~127 범위 내
Character c2 = Character.valueOf('A');  // 같은 객체
Character c3 = Character.valueOf('가'); // 범위 밖
Character c4 = Character.valueOf('가'); // 다른 객체
c1 == c2;  // true
c3 == c4;  // false

// Boolean 캐시
Boolean b1 = Boolean.valueOf(true);   // 항상 캐시
Boolean b2 = Boolean.valueOf(true);   // 같은 객체
Boolean b3 = Boolean.valueOf(false); // 항상 캐시
Boolean b4 = Boolean.valueOf(false); // 같은 객체
b1 == b2;  // true
b3 == b4;  // true

// Float, Double은 캐시 없음
Float f1 = Float.valueOf(1.0f);
Float f2 = Float.valueOf(1.0f);
f1 == f2;  // false (항상 다른 객체)

-1은 캐시 범위 내이므로 캐시된 Long 객체를 반환합니다.

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스                            │
│  - STR: → "ABC" 주소값               │
│  - l:   → [주소값]                   │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  Long(-1L) 객체                      │
└─────────────────────────────────────┘

주소 관계:

Method Area (l 변수) → Heap (Long 객체)

2-2-3. private static int i = -1;

⚠️ 중요: Primitive 타입은 주소값이 아닌 값 자체를 저장합니다!

1. Method Area의 i 변수에 직접 값(-1) 저장
   (Primitive 타입은 주소값 없이 값 자체 저장)

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스                            │
│  - STR: → "ABC" 주소값               │
│  - l:   → Long 객체 주소값           │
│  - i:   -1 (값 직접 저장)            │
└─────────────────────────────────────┘

2-2-4. private static C c = new C();

⚠️ 중요: C 클래스가 아직 로드되지 않았으므로 C 클래스 로드부터 시작!

이것이 Lazy Loading의 핵심입니다. static 변수 초기화 중에 다른 클래스가 필요하면 그 클래스를 먼저 로드합니다.

1. C 클래스 로드 필요
   ↓
2. Application Class Loader가 C.class 파일을 읽음
   ↓
3. C 클래스 정보를 Method Area에 로드
   ↓
4. C 클래스의 static 변수 초기화 (없음)
   ↓
5. C 클래스의 static 블록 실행
   ↓
6. new C() 실행

C 클래스 로드 과정:

메모리 상태 (C 클래스 로드 후):

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스                            │
│  - STR: → "ABC" 주소값               │
│  - l:   → Long 객체 주소값           │
│  - i:   -1                           │
│  - c:   null (아직 초기화 안됨)      │
│                                     │
│  C 클래스 메타데이터                 │
│  - (static 변수 없음)                │
└─────────────────────────────────────┘

new C() 실행:

1. Heap에 C 객체 생성 공간 할당
   ↓
2. C 객체의 인스턴스 변수 초기화
   ↓
3. C 인스턴스 블록 실행
   ↓
4. C 생성자 실행
   ↓
5. Method Area의 c 변수에 C 객체 주소값 저장

메모리 상태 (C 객체 생성 후):

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스                            │
│  - STR: → "ABC" 주소값               │
│  - l:   → Long 객체 주소값           │
│  - i:   -1                           │
│  - c:   → [주소값]                   │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  C 객체 (static)                    │
└─────────────────────────────────────┘

주소 관계:

Method Area (c 변수) → Heap (C 객체)

2-3. A 클래스의 Static 블록 실행

모든 static 변수 초기화가 완료되면 static 블록이 실행됩니다.

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area (A 클래스)              │
├─────────────────────────────────────┤
│  STR: → "ABC" 주소값                 │
│  l:   → Long 객체 주소값             │
│  i:   -1 (값 직접 저장)             │
│  c:   → C 객체 주소값                │
└─────────────────────────────────────┘

🎯 3단계: main 메서드 실행

3-1. main 메서드 호출

JVM이 main 메서드를 찾아서 실행합니다:

JVM이 main 메서드를 찾아서 실행
  ↓
main 메서드의 지역 변수들이 Stack에 할당됨

메모리 상태:

┌─────────────────────────────────────┐
│  Stack                              │
├─────────────────────────────────────┤
│  main 메서드 스택 프레임             │
│  - args: → [String 배열 주소값]      │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  String[] 배열                      │
└─────────────────────────────────────┘

🏗️ 4단계: A 객체 생성 (A a = new A();)

⚠️ 핵심 포인트: 객체 생성 순서

객체 생성은 다음 순서로 진행됩니다:

  1. Heap에 메모리 할당
  2. 인스턴스 변수 초기화 (선언 순서대로)
  3. 인스턴스 블록 실행
  4. 생성자 실행

4-1. new A() 호출

1. Heap에 A 객체 생성 공간 할당
   ↓
2. A 객체의 인스턴스 변수 초기화 (선언 순서대로)

4-2. 인스턴스 변수 초기화

4-2-1. private final String a = "ABC";

⚠️ 중요: String Constant Pool에 이미 존재하므로 재사용!

1. "ABC" 리터럴 확인
   ↓
2. String Constant Pool에 이미 존재 (2-2-1에서 생성됨)
   ↓
3. Heap의 A 객체 내부에 a 변수 공간 생성
   ↓
4. a 변수에 String Constant Pool의 "ABC" 주소값 저장

메모리 상태:

  • Heap (A 객체 내부):
    • a 변수: String Constant Pool의 "ABC" 주소값 저장

주소 관계:

┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  A 객체                              │
│  - a: → [주소값]                     │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap (String Constant Pool)         │
├─────────────────────────────────────┤
│  "ABC" String 객체                  │
│  ↑                                  │
│  └─ A.STR과 a.a가 모두 참조!        │
└─────────────────────────────────────┘

⚠️ 핵심: A.STR과 a.a는 같은 "ABC" 객체를 가리킵니다!

4-2-2. private final int ii = 1;

1. Heap의 A 객체 내부에 ii 변수 공간 생성
   ↓
2. ii 변수에 값 1 직접 저장

메모리 상태:

┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  A 객체                              │
│  - a:  → "ABC" 주소값                │
│  - ii: 1 (값 직접 저장)              │
└─────────────────────────────────────┘

4-2-3. private C cc = new C("instance");

1. new C("instance") 실행
   ↓
2. Heap에 C 객체 생성 공간 할당
   ↓
3. C 객체의 인스턴스 변수 초기화
   ↓
4. C 인스턴스 블록 실행
   ↓
5. C 생성자 실행
   ↓
6. Heap의 A 객체 내부에 cc 변수 공간 생성
   ↓
7. cc 변수에 C 객체 주소값 저장

메모리 상태:

┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  A 객체                              │
│  - a:  → "ABC" 주소값                │
│  - ii: 1                             │
│  - cc: → [주소값]                    │
│                                     │
│  C 객체 (A의 인스턴스)               │
│  - type: "instance"                  │
└─────────────────────────────────────┘

주소 관계:

Heap (A 객체 내부의 cc 변수) → Heap (C 객체)

4-3. A 인스턴스 블록 실행

모든 인스턴스 변수 초기화가 완료되면 인스턴스 블록이 실행됩니다.

4-4. A 생성자 실행

생성자가 실행되면 인스턴스 변수들을 사용할 수 있습니다.

메모리 상태:

┌─────────────────────────────────────┐
│  Stack                              │
├─────────────────────────────────────┤
│  main 메서드 스택 프레임              │
│  - args: → String 배열 주소값        │
│  - a:    → [주소값]                  │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  A 객체                              │
│  - a:  → "ABC" 주소값                │
│  - ii: 1                             │
│  - cc: → C 객체 주소값               │
└─────────────────────────────────────┘

주소 관계:

Stack (main의 a 변수) → Heap (A 객체)

🔄 5단계: B 객체 생성 (B b = new B();)

⚠️ 핵심 포인트: 상속 관계에서의 초기화 순서

상속 관계에서는 부모 클래스부터 초기화됩니다:

  1. 부모 클래스 인스턴스 변수 초기화
  2. 부모 클래스 인스턴스 블록 실행
  3. 부모 클래스 생성자 실행
  4. 자식 클래스 인스턴스 변수 초기화
  5. 자식 클래스 인스턴스 블록 실행
  6. 자식 클래스 생성자 실행

5-1. B 클래스 로드 (Lazy Loading)

B 클래스가 처음 사용되므로 로드가 필요합니다:

1. B 클래스가 처음 사용됨
   ↓
2. Application Class Loader가 B.class 파일을 읽음
   ↓
3. B 클래스 정보를 Method Area에 로드
   ↓
4. B는 A를 상속받으므로 A 클래스 정보도 확인 (이미 로드됨)
   ↓
5. B 클래스의 static 변수 초기화 (없음)
   ↓
6. B 클래스의 static 블록 실행

메모리 상태:

┌─────────────────────────────────────┐
│  Method Area                        │
├─────────────────────────────────────┤
│  A 클래스 메타데이터                 │
│  B 클래스 메타데이터                 │
│  - 부모 클래스: A                    │
│  - (static 변수 없음)                │
└─────────────────────────────────────┘

5-2. new B() 호출

1. Heap에 B 객체 생성 공간 할당
   ↓
2. B는 A를 상속받으므로 A의 인스턴스 변수들도 포함
   ↓
3. 인스턴스 변수 초기화 (부모부터)

5-3. 인스턴스 변수 초기화 (상속받은 A의 변수들)

5-3-1. A의 인스턴스 변수들 초기화

1. private final String a = "ABC";
   - String Constant Pool의 "ABC" 주소값 저장
   
2. private final int ii = 1;
   - 값 1 직접 저장
   
3. private C cc = new C("instance");
   - 새 C 객체 생성
   - cc 변수에 C 객체 주소값 저장

메모리 상태:

┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  B 객체 (A의 변수들 포함)                │
│  - a:  → "ABC" 주소값                 │
│  - ii: 1                            │
│  - cc: → [주소값]                     │
│                                     │   
│  C 객체 (B의 인스턴스)                  │
│  - type: "instance"                 │
└─────────────────────────────────────┘

5-4. A 인스턴스 블록 실행 (상속)

B 객체이지만 A를 상속받았으므로 A의 인스턴스 블록이 실행됩니다.

5-5. A 생성자 실행 (super() 호출)

B 생성자에서 암묵적으로 super()가 호출되어 A 생성자가 실행됩니다.

5-6. B 인스턴스 블록 실행

B의 인스턴스 블록이 실행됩니다.

5-7. B 생성자 실행

B 생성자가 실행됩니다.

메모리 상태:

┌─────────────────────────────────────┐
│  Stack                              │
├─────────────────────────────────────┤
│  main 메서드 스택 프레임                 │
│  - args: → String 배열 주소값          │
│  - a:    → A 객체 주소값               │
│  - b:    → [주소값]                   │
└─────────────────────────────────────┘
         ↓
┌─────────────────────────────────────┐
│  Heap                               │
├─────────────────────────────────────┤
│  B 객체 (A 상속)                       │
│  - a:  → "ABC" 주소값                 │
│  - ii: 1                            │
│  - cc: → C 객체 주소값                 │
└─────────────────────────────────────┘

주소 관계:

Stack (main의 b 변수) → Heap (B 객체)

🎓 핵심 정리

1. ⚠️ Class Loader는 Lazy Loading

클래스는 처음 사용될 때만 로드됩니다!

  • 프로그램 시작 시 모든 클래스를 로드하지 않음
  • 필요할 때마다 동적으로 로드
  • 메모리 효율성과 시작 시간 단축에 유리

예시:

  • A 클래스 로드 시 C 클래스가 필요하면 그때 C 클래스 로드
  • B 클래스는 new B() 호출 시점에 로드

2. ⚠️ Static 변수는 Method Area

클래스 로드 시 1번만 초기화되며, 모든 객체가 공유합니다!

특징:

  • 클래스 레벨의 변수
  • 객체 생성과 무관하게 존재
  • 모든 인스턴스가 같은 값을 공유
  • GC가 수집하지 않음 (프로그램 종료 시까지 유지)

메모리 위치:

Method Area (클래스당 1개)
  └─ Static 변수들

3. ⚠️ 인스턴스 변수는 Heap

객체 생성 시마다 초기화되며, 객체마다 별도로 존재합니다!

특징:

  • 객체 레벨의 변수
  • 객체 생성 시마다 새로 할당
  • 각 객체가 독립적인 값을 가짐
  • GC가 수집 가능

메모리 위치:

Heap (객체마다 별도)
  └─ 인스턴스 변수들

4. ⚠️ 주소값 저장 위치

변수가 있는 곳과 같은 위치에 주소값이 저장됩니다!

  • Method Area 변수 → Method Area에 주소값 저장
  • Heap 변수 → Heap에 주소값 저장
  • Stack 변수 → Stack에 주소값 저장

예시:

Method Area (A.STR) → Heap ("ABC" 객체)
Heap (a.cc)         → Heap (C 객체)
Stack (main.a)      → Heap (A 객체)

5. ⚠️ 상속 관계에서의 초기화 순서

부모 클래스의 초기화 블록과 생성자가 먼저 실행됩니다!

부모 클래스 인스턴스 변수 초기화
  ↓
부모 클래스 인스턴스 블록 실행
  ↓
부모 클래스 생성자 실행
  ↓
자식 클래스 인스턴스 변수 초기화
  ↓
자식 클래스 인스턴스 블록 실행
  ↓
자식 클래스 생성자 실행

6. ⚠️ String Constant Pool

같은 리터럴은 같은 객체를 참조합니다!

이는 메모리 효율성을 위한 최적화입니다.

예시:

  • A.STR과 a.a는 같은 "ABC" 객체를 참조
  • b.a도 같은 "ABC" 객체를 참조
  • new String("ABC")는 새로운 객체를 생성하므로 다른 주소값

💡 실무에서의 활용

⚠️ 메모리 누수 방지

Static 변수에 큰 객체를 저장하면 GC가 수집하지 못해 메모리 누수가 발생할 수 있습니다!

// ❌ 나쁜 예
class Cache {
    private static Map<String, Object> cache = new HashMap<>();
    // 이 Map은 프로그램 종료 시까지 메모리에 남음
}

// ✅ 좋은 예
class Cache {
    private static final int MAX_SIZE = 1000;
    private static Map<String, Object> cache = new LinkedHashMap<String, Object>() {
        @Override
        protected boolean removeEldestEntry(Map.Entry<String, Object> eldest) {
            return size() > MAX_SIZE;
        }
    };
}

클래스 로딩 최적화

불필요한 클래스 로딩을 피하면 시작 시간을 단축할 수 있습니다!

// ❌ 나쁜 예: 모든 클래스를 미리 로드
static {
    ClassA.init();
    ClassB.init();
    ClassC.init();
}

// ✅ 좋은 예: 필요할 때만 로드
public static ClassA getClassA() {
    if (classA == null) {
        classA = new ClassA();
    }
    return classA;
}

String Constant Pool 활용

문자열 비교 시 equals() 대신 ==를 사용할 수 있지만, 이는 리터럴에만 해당합니다!

String s1 = "ABC";  // String Constant Pool
String s2 = "ABC";  // String Constant Pool
String s3 = new String("ABC");  // Heap (새 객체)

s1 == s2;  // true (같은 객체)
s1 == s3;  // false (다른 객체)
s1.equals(s3);  // true (값은 같음)
