Go로 CLI 도구 만들기: Cobra 라이브러리 활용

CLI 개념을 정리하면서 직접 CLI 도구를 만들어보기

2025년 11월 27일 오후 04:19

안녕하세요! 오늘은 Go로 CLI 도구를 만들어보면서 배운 내용들을 정리해보려고 합니다.

최근에 CLI의 개념을 정리하면서, 직접 CLI 도구를 만들어보면 더 잘 이해할 수 있지 않을까 하는 생각이 들었습니다. 처음엔 뭐로 만들어야 할지 감도 못 잡았는데, 조사해보니 Go로 만든 CLI 도구들이 훨씬 가볍고 배포가 간단하더라구요.

이 글에서는 Go로 CLI 도구를 처음 만들어본 경험과 배운 점들을 공유합니다.

🎯 왜 Go로 CLI를 만들게 되었나?

왜 Go를 선택했나?

CLI 도구를 만들 때 어떤 언어를 써야 할지 고민이 많았습니다. 여러 옵션을 비교해보니 Go가 가장 적합해 보였어요.

구분다른 언어들Go
📦 배포런타임 또는 JVM 필요단일 실행 파일
⚡ 실행 속도런타임 시작 시간 필요즉시 실행
💾 파일 크기런타임 포함 시 크거나 의존성 많음실행 파일만 (~5-10MB)
🌐 배포 편의성런타임 설치 필요플랫폼별 빌드만 필요
🔧 의존성 관리복잡한 설정 필요go.mod로 간단

특히 배포 측면에서 Go가 가장 유리합니다. 다른 언어들은 런타임 설치가 필요하지만, Go는 빌드된 실행 파일 하나만 있으면 바로 실행할 수 있어요.

Go CLI의 장점

실제로 많은 유명한 CLI 도구들이 Go로 만들어져 있습니다:

  • Docker CLI: 컨테이너 관리 도구
  • Kubernetes (kubectl): 쿠버네티스 클러스터 관리
  • Terraform: 인프라 코드 관리
  • GitHub CLI (gh): GitHub 작업 자동화

이런 도구들이 Go를 선택한 이유는 배포의 편리함과 실행 속도 때문입니다.

🚀 프로젝트 시작하기

1. 프로젝트 구조 설계

Go 프로젝트는 명확한 구조를 가지고 있습니다. 처음엔 main.go 하나만 있으면 되지 않나 싶었는데, 확장성을 고려하면 구조를 잡는 게 좋을 것 같았습니다.

my-go-cli/
├── cmd/
│   └── gotool/
│       └── main.go          # 실행 진입점
├── internal/
│   └── commands/            # 각 커맨드 로직
│       ├── port.go
│       ├── uuid.go
│       ├── base64.go
│       ├── time.go
│       └── ip.go
├── go.mod
└── go.sum

구조 설명:

  • cmd/gotool/: 실행 가능한 애플리케이션 진입점
  • internal/commands/: 외부에서 import 불가능한 내부 패키지 (프로젝트 내부 전용)
*프로젝트 디렉토리 구조 - cmd와 internal 폴더로 명확하게 분리*

2. Cobra 라이브러리 선택

Go에서 CLI를 만들 때 가장 많이 사용하는 라이브러리는 Cobra입니다. Kubernetes, Docker, GitHub CLI 등 많은 도구들이 Cobra를 사용해요.

Cobra의 장점:

  • 서브커맨드 지원
  • 플래그(옵션) 관리
  • 자동 도움말 생성
  • 명령어 자동완성 지원
*Cobra 라이브러리 설치 - go get 명령어로 의존성 추가*

🛠️ 기본 구조 이해하기

Cobra Command 구조

Cobra의 Command는 다음과 같습니다:

var rootCmd = &cobra.Command{
    Use:   "gotool",                    // 명령어 이름
    Short: "개발자용 유틸리티 CLI 도구",  // 짧은 설명
    Long:  "Go로 만든 개발자용 유틸리티 CLI 도구입니다.", // 긴 설명
    Version: "1.0.0",                  // 버전 정보
}

포인터 이해하기:

  • &cobra.Command{...}: 구조체의 포인터를 만듦
  • cmd *cobra.Command: 포인터 타입 파라미터

Go는 포인터를 명시적으로 사용하는데, 처음엔 헷갈렸지만 익숙해지니 오히려 메모리 관리가 명확해서 좋았습니다.

서브커맨드 구현

각 기능을 서브커맨드로 구현했습니다:

func main() {
    var rootCmd = &cobra.Command{
        Use:     "gotool",
        Short:   "개발자용 유틸리티 CLI 도구",
        Version: version,
    }

    rootCmd.AddCommand(commands.PortCmd())      // 포트 체크
    rootCmd.AddCommand(commands.UuidCmd())      // UUID 생성
    rootCmd.AddCommand(commands.Base64Cmd())    // Base64 인코딩/디코딩
    rootCmd.AddCommand(commands.TimeCmd())      // 타임스탬프 변환
    rootCmd.AddCommand(commands.IpCmd())         // IP 확인
}

각 커맨드는 internal/commands/ 폴더에 별도 파일로 분리하여 유지보수성을 높였습니다.

*gotool --help 실행 화면 - 모든 서브커맨드가 표시됨*

📦 구현한 기능들

1. 포트 체크 (gotool port [포트번호])

특정 포트가 사용 중인지 확인하는 기능입니다. 개발 중에 포트 충돌을 확인할 때 유용해요.

func PortCmd() *cobra.Command {
    return &cobra.Command{
        Use:   "port [포트번호]",
        Short: "포트 사용 여부 확인",
        Run: func(cmd *cobra.Command, args []string) {
            // 포트 체크 로직
        },
    }
}

사용 예시:

*포트 체크 기능 실행 화면 - 사용 중인 포트와 사용 가능한 포트 확인*

2. UUID 생성 (gotool uuid)

새로운 UUID v4를 생성합니다. 테스트 데이터 생성이나 임시 ID가 필요할 때 사용해요.

*UUID 생성 기능 실행 화면 - 새로운 UUID v4 출력*

3. Base64 인코딩/디코딩 (gotool base64 encode/decode)

텍스트를 Base64로 인코딩하거나 디코딩합니다. API 테스트나 데이터 변환이 필요할 때 유용해요.

*Base64 인코딩/디코딩 기능 실행 화면 - 텍스트 변환 결과*

4. 타임스탬프 변환 (gotool time [타임스탬프])

Unix 타임스탬프를 읽기 쉬운 날짜 형식으로 변환합니다. 로그 분석이나 디버깅 시 유용해요.

*타임스탬프 변환 기능 실행 화면 - Unix 타임스탬프를 날짜 형식으로 변환*

5. IP 확인 (gotool ip)

로컬 네트워크 인터페이스의 IP 주소를 확인합니다. 네트워크 설정 확인 시 유용해요.

🔨 빌드 및 배포

로컬 빌드

go build -o gotool cmd/gotool/main.go

이 명령어 하나로 모든 의존성이 포함된 실행 파일이 생성됩니다. 별도의 패키징 과정이 필요 없어요.

PATH에 등록 (macOS)

# 빌드
go build -o gotool cmd/gotool/main.go

# PATH에 등록
sudo cp gotool /usr/local/bin/

# 실행
gotool --version

이제 어디서든 gotool 명령어를 사용할 수 있어요!

*버전 확인 - gotool --version 실행 화면*

제거

sudo rm /usr/local/bin/gotool

💡 Go를 배우면서 느낀 점

1. 타입 시스템

Go는 정적 타입 언어지만 타입 추론을 지원해요:

// 명시적 타입 선언
var name string = "값"

// 타입 추론 (:= 사용)
name := "값"  // 타입이 자동으로 추론됨

타입 추론을 지원하면서도 :=를 사용해서 선언과 할당을 동시에 할 수 있어요.

2. 에러 처리

Go는 예외(Exception) 대신 에러를 일반 반환값으로 처리해요:

result, err := someFunction()
if err != nil {
    // 에러 처리
    return err
}

처음엔 "에러를 매번 체크해야 하네?" 싶었지만, 명시적인 에러 처리가 오히려 코드를 더 명확하게 만들어줍니다.

3. 포인터

Go는 포인터를 명시적으로 사용합니다:

var rootCmd = &cobra.Command{...}  // & = 주소를 만들어서 저장
func run(cmd *cobra.Command) {    // * = 포인터 타입 선언
    // ...
}

처음엔 헷갈렸지만, 메모리 관리가 명확해서 좋았습니다.

4. 패키지 구조

Go는 internal/ 패키지를 통해 외부에서 import를 막을 수 있습니다. 내부 구현을 숨기고 API를 명확하게 관리할 수 있어요.

🎯 결과 및 개선점

1. 개발 편의성

  • 빠른 빌드: Go의 컴파일 속도가 정말 빠름
  • 간단한 배포: 단일 실행 파일로 배포 가능
  • 명확한 구조: 프로젝트 구조가 직관적

2. 성능

  • 즉시 실행: 런타임 시작 시간 없이 바로 실행
  • 작은 파일 크기: 실행 파일만 5-10MB 정도

3. 확장성

  • 모듈화: 각 커맨드를 별도 파일로 분리하여 유지보수 용이
  • 의존성 관리: go.mod로 간단한 의존성 관리

📋 결론

CLI 도구를 만들어보면서 Go가 CLI 개발에 꽤 편하다는 걸 느꼈습니다. 특히 단일 실행 파일로 빌드되는 점과 간단한 의존성 관리가 인상적이었어요. 물론 용도에 따라 다른 언어를 선택할 수도 있지만, 이번 프로젝트에는 Go가 잘 맞았어요.

이번에 간단한 CLI 도구만 만들어봤지만, Go의 기본적인 문법과 구조를 이해할 수 있었습니다. 더 복잡한 프로젝트를 만들면 더 많은 걸 배울 수 있을 것 같아요.

솔직히 말하면, 처음에는 "Go를 또 배워야 하나?" 하는 생각이 들었습니다. 하지만 실제로 CLI 도구를 만들어보니, Go가 이 용도에는 정말 적합하다는 걸 알게 되었어요.

간단한 도구 하나 만들면서 Go의 기본 문법과 구조를 익힐 수 있었고, 앞으로 더 복잡한 프로젝트를 만들 때도 도움이 될 것 같습니다.
