[6년차 쯤 되면 좀 알자]

가상머신과 하이퍼바이저에 대해 정리하다 보니, "커널"이라는 용어가 자주 나오는데 정확히 무엇인지 궁금해졌습니다. 대충 "시스템 소통 창구" 정도로 이해하고 있었는데, 실제로는 어떤 역할을 하는지 자세히 알아볼게요.

커널이란?

커널(Kernel)은 운영체제(OS)의 핵심 구성 요소로, 하드웨어와 소프트웨어 간의 중재자 역할을 해요. 단순히 "소통 창구"라기보다는, 시스템의 모든 리소스를 관리하고 프로그램들이 하드웨어를 안전하게 사용할 수 있도록 보장하는 운영체제의 엔진입니다.

커널의 핵심 역할

커널은 다음과 같은 핵심 역할을 수행해요:

  1. 하드웨어 추상화: 프로그램이 하드웨어를 직접 다루지 않고도 사용할 수 있도록 표준화된 인터페이스를 제공
  2. 리소스 관리: CPU, 메모리, 디스크, 네트워크 등 시스템 자원을 효율적으로 할당하고 관리
  3. 보안과 격리: 프로세스 간 격리와 권한 관리를 통해 시스템의 안정성과 보안을 유지

OS와 커널의 관계

많은 사람들이 OS와 커널을 혼동하는데, 정확한 관계는 다음과 같아요:

┌─────────────────────────────────┐
│  사용자 프로그램 (User Space)       │  ← 우리가 만드는 앱들
├─────────────────────────────────┤
│  Shell, GUI, 시스템 도구           │  ← OS의 사용자 인터페이스
│  (bash, zsh, ls, cd, ps 등)      │
├─────────────────────────────────┤
│  라이브러리 (libc, stdlib 등)      │  ← OS의 지원 라이브러리
├─────────────────────────────────┤
│  커널 (Kernel Space)             │  ← OS의 핵심 엔진!
│  - 프로세스 관리                   │
│  - 메모리 관리                     │
│  - 파일 시스템                     │
│  - 장치 드라이버                   │
│  - 네트워크 스택                   │
├─────────────────────────────────┤
│  하드웨어                         │
└─────────────────────────────────┘

OS = 커널 + Shell + 시스템 도구 + 라이브러리

  • 커널: OS의 핵심 엔진으로, 하드웨어를 직접 제어하고 리소스를 관리
  • Shell: 사용자와 커널을 연결하는 인터페이스 (터미널에서 사용하는 명령어 해석기)
  • 시스템 도구: ls, cd, ps, grep 같은 명령어들
  • 라이브러리: 프로그램이 커널 기능을 쉽게 사용할 수 있도록 제공하는 함수들

비유:

  • 하드웨어: 건물
  • 커널: 건물 관리사무소 (리소스 관리, 보안, 접근 제어)
  • Shell: 관리사무소 접수 창구
  • 프로그램: 입주자들

커널의 주요 기능

1. 프로세스 관리

여러 프로그램이 동시에 실행되도록 CPU 시간을 분배해요:

프로그램 A 실행 (10ms)
    ↓
커널이 제어권 가져옴 (Context Switch)
    ↓
프로그램 B 실행 (10ms)
    ↓
커널이 제어권 가져옴
    ↓
프로그램 C 실행 (10ms)
    ↓
반복...

주요 작업:

  • 프로세스 생성, 종료, 일시정지
  • CPU 스케줄링 (어떤 프로세스를 언제 실행할지 결정)
  • 프로세스 간 통신 (IPC: Inter-Process Communication)

2. 메모리 관리

각 프로세스에 메모리를 할당하고, 프로세스 간 메모리 접근을 제어:

가상 메모리와 물리 메모리:

각 프로세스는 자신만의 **가상 주소 공간(Virtual Address Space)**을 가져요. 프로세스는 물리 메모리를 직접 다루지 않고, 가상 주소를 사용해요. 커널이 이 가상 주소를 물리 주소로 변환해줘요.

왜 같은 가상 주소인데 물리 주소가 다른가요?

각 프로세스마다 독립적인 페이지 테이블(Page Table)이 있어요. 같은 가상 주소라도 프로세스마다 다른 물리 주소를 가리키도록 매핑돼요:

프로세스 A의 페이지 테이블:
  가상 주소 0x1000 → 물리 주소 0x5000

프로세스 B의 페이지 테이블:
  가상 주소 0x1000 → 물리 주소 0x8000
  (같은 가상 주소지만 다른 물리 메모리!)

프로세스 C의 페이지 테이블:
  가상 주소 0x1000 → 물리 주소 0x2000

작동 원리:

  1. 프로세스 A가 가상 주소 0x1000에 접근하려고 해요
  2. MMU(Memory Management Unit)가 프로세스 A의 페이지 테이블을 참조해요
  3. 페이지 테이블에서 "가상 주소 0x1000 → 물리 주소 0x5000"을 찾아요
  4. 실제로는 물리 주소 0x5000에 접근해요

프로세스 B가 같은 가상 주소 0x1000에 접근해도:

  1. MMU가 프로세스 B의 페이지 테이블을 참조해요 (프로세스 A와 다른 테이블!)
  2. 프로세스 B의 페이지 테이블에서 "가상 주소 0x1000 → 물리 주소 0x8000"을 찾아요
  3. 실제로는 물리 주소 0x8000에 접근해요 (프로세스 A와 다른 물리 메모리!)

메모리 격리:

프로그램 A: 가상 주소 0x1000 → 물리 주소 0x5000
프로그램 B: 가상 주소 0x1000 → 물리 주소 0x8000
           (같은 가상 주소지만 다른 물리 메모리!)

커널이 각 프로세스의 페이지 테이블을 관리하여 메모리를 격리해요.

주요 작업:

  • 메모리 할당 및 해제
  • 가상 메모리 관리 (페이지 테이블 관리)
  • 메모리 보호 (한 프로세스가 다른 프로세스의 메모리에 접근하지 못하도록)

3. 파일 시스템 관리

파일의 생성, 읽기, 쓰기, 삭제 등을 관리해요:

주요 작업:

  • 파일 및 디렉토리 관리
  • 디스크 공간 할당
  • 파일 권한 관리
  • 다양한 파일 시스템 지원 (ext4, NTFS, FAT32 등)

4. 장치 관리 (I/O 관리)

하드웨어 장치와의 통신을 담당해요:

주요 작업:

  • 장치 드라이버 관리
  • 키보드, 마우스, 디스크, 네트워크 카드 등 다양한 장치와의 통신
  • 장치 간 충돌 방지

5. 보안 및 접근 제어

사용자와 프로세스의 권한을 관리해요:

주요 작업:

  • 사용자 인증 및 권한 관리
  • 파일 및 시스템 리소스 접근 제어
  • 프로세스 간 격리

System Call: 커널과 프로그램의 소통 창구

프로그램이 하드웨어에 접근하려면 커널을 거쳐야 해요. 이때 사용하는 것이 System Call (시스템 호출)이에요.

System Call의 작동 원리

1. 프로그램이 System Call 호출
   예: 파일 읽기 요청

2. CPU가 User Mode → Kernel Mode로 전환
   (권한 레벨 변경: Ring 3 → Ring 0)

3. 커널이 요청을 처리
   - 권한 확인
   - 하드웨어 접근
   - 데이터 읽기

4. 결과를 프로그램에 반환

5. CPU가 Kernel Mode → User Mode로 전환
   (권한 레벨 변경: Ring 0 → Ring 3)

System Call 예시

// 사용자 프로그램
FILE *file = fopen("data.txt", "r");  // ← 내부적으로 System Call 호출

// 실제로는:
// 1. open() System Call 호출
// 2. 커널이 권한 확인
// 3. 커널이 디스크에서 파일 읽기
// 4. 커널이 파일 디스크립터 반환

주요 System Call:

  • open(), read(), write(), close(): 파일 작업
  • fork(), exec(), exit(): 프로세스 관리
  • malloc(), free(): 메모리 할당
  • socket(), bind(), connect(): 네트워크 통신

Kernel Space vs User Space

커널은 메모리 공간을 두 영역으로 나눠요:

User Space (사용자 공간):

  • 일반 프로그램이 실행되는 영역
  • Ring 3 권한 (제한된 권한)
  • 하드웨어에 직접 접근 불가
  • System Call을 통해서만 커널 기능 사용 가능

Kernel Space (커널 공간):

  • 커널이 실행되는 영역
  • Ring 0 권한 (최고 권한)
  • 하드웨어에 직접 접근 가능
  • 모든 시스템 리소스 제어 가능
┌─────────────────────────────────┐
│  User Space (Ring 3)            │  ← 프로그램 실행
│  - 제한된 권한                     │
│  - System Call로 커널 접근         │
├─────────────────────────────────┤
│  Kernel Space (Ring 0)          │  ← 커널 실행
│  - 최고 권한                      │
│  - 하드웨어 직접 접근               │
└─────────────────────────────────┘

커널의 종류

커널은 설계 방식에 따라 여러 종류로 나뉘어요:

1. 모놀리식 커널 (Monolithic Kernel)

운영체제의 모든 기본 서비스가 하나의 커널 공간에서 실행돼요.

특징:

  • 성능이 우수해요 (함수 호출로 직접 통신)
  • 커널 크기가 커져요
  • 한 모듈의 오류가 전체 시스템에 영향을 줄 수 있어요

예시: Linux, Unix

구조:

┌─────────────────────────────────┐
│  모든 서비스가 하나의 커널 공간        │
│  - 파일 시스템                     │
│  - 메모리 관리                     │
│  - 프로세스 관리                   │
│  - 네트워크 스택                   │
│  - 장치 드라이버                   │
└─────────────────────────────────┘

2. 마이크로커널 (Microkernel)

기본적인 기능만 커널 공간에서 실행하고, 나머지 서비스는 사용자 공간에서 실행해요.

특징:

  • 안정성이 높아요 (한 서비스의 오류가 커널에 영향을 주지 않음)
  • 모듈화가 잘 되어 있어요
  • 성능이 다소 저하될 수 있어요 (프로세스 간 통신 오버헤드)

예시: QNX, MINIX

구조:

┌─────────────────────────────────┐
│  커널 공간 (최소 기능만)             │
│  - 프로세스 관리                   │
│  - 메모리 관리                     │
│  - 프로세스 간 통신                 │
├─────────────────────────────────┤
│  사용자 공간 (나머지 서비스)          │
│  - 파일 시스템                     │
│  - 네트워크 스택                   │
│  - 장치 드라이버                   │
└─────────────────────────────────┘

3. 하이브리드 커널 (Hybrid Kernel)

모놀리식 커널과 마이크로커널의 장점을 결합한 형태예요.

특징:

  • 주요 서비스는 커널 공간에서 실행 (성능)
  • 일부 서비스는 사용자 공간에서 실행 (안정성)

예시: Windows, macOS

커널과 하이퍼바이저의 관계

앞서 다룬 하이퍼바이저와 커널의 관계를 정리하면:

┌─────────────────────────────────┐
│  Guest OS (VM 내부)              │
│  ┌───────────────────────────┐  │
│  │ 사용자 프로그램               │  │
│  ├───────────────────────────┤  │
│  │ 커널 (Guest OS의 커널)       │  │  ← VM 내부의 커널
│  └───────────────────────────┘  │
├─────────────────────────────────┤
│  하이퍼바이저                      │  ← VM을 관리하는 "커널의 커널"
│  (자체 커널 포함)                  │
├─────────────────────────────────┤
│  물리 하드웨어                     │
└─────────────────────────────────┘

비교:

  • 커널: 하나의 OS 내에서 하드웨어를 관리
  • 하이퍼바이저: 여러 OS(VM)를 관리하는 "커널의 커널" 같은 역할

Type 1 하이퍼바이저(예: VMware ESXi, KVM)는 자체 커널을 가지고 있어요.

정리

커널은:

  • "시스템 소통 창구" 맞아요, 하지만 그 이상이에요
  • OS의 핵심 엔진으로, 하드웨어와 소프트웨어 사이의 중재자이자 리소스 관리자예요
  • System Call을 통해 프로그램이 하드웨어를 안전하게 사용할 수 있게 해줘요
  • 프로세스, 메모리, 파일 시스템, 장치 등을 관리하여 시스템의 안정성과 효율성을 유지해요

OS와 커널의 관계:

  • OS = 커널 + Shell + 시스템 도구 + 라이브러리
  • 커널은 OS의 핵심이지만, OS 전체는 아니에요

비유:

  • 하드웨어 = 건물
  • 커널 = 건물 관리사무소 (리소스 관리, 보안, 접근 제어)
  • Shell = 관리사무소 접수 창구
  • 프로그램 = 입주자들

면접에서 "커널이 무엇인가요?"라는 질문에는 단순히 "시스템 소통 창구"가 아니라, "OS의 핵심 구성 요소로, 하드웨어와 소프트웨어 간의 중재자 역할을 하며, 프로세스 관리, 메모리 관리, 파일 시스템 관리, 장치 관리, 보안 및 접근 제어를 담당한다"고 구체적으로 설명하면 돼요.
